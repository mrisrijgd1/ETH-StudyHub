Why it matters for the exam

Every IFMP exam from 2015 to 2018 opens with a task called "Typen und Werte / Types and values": six expressions, give the C++ type (0.5 P) and value (1 P) of each, 6 to 9 points out of 60. All of them are on this page with full solutions. Your exam is at the computer, but the same knowledge decides whether your code computes what you think: 9 / 5 silently being 1 is the most common bug in first programs. The official exams warn: "integer or boolean are not C++ types and will be considered as incorrect answers". Write int, unsigned int, float, double, bool.

Recap of lesson 1 (5 minutes)

A program runs top to bottom inside main. A variable is a box with type, name, value and address; an assignment evaluates the right side and then stores it on the left. An expression has a type, a value, and possibly an effect. Check yourself:

  1. After int a = 4; int b = a; a = a + b;, what are a and b?
    Answer

    a: 4, 8 and b: 4. b = a copied the value 4; changing a later doesn't change b.

  2. Why does a + b = 3; not compile?
    Answer

    a + b is an rvalue: it has no address, so nothing can be stored in it. The left side of = must be an lvalue, a box.

1. The story: boxes of different shapes

The golem's workshop has more kinds of boxes than it seemed on the first day. Whole-number boxes are narrow and exact, but they have a top and a bottom: pour in too much and the result is no longer to be trusted. Clock boxes hold only numbers from zero up, and they wrap around like the clock dials of the Free City's guilds: one past the top is zero again. Float boxes hold fractions and enormous numbers, but they are made of mesh: some values simply fall through the holes and the box keeps the nearest one it can hold. And the smallest boxes of all hold only a yes or a no.

When an order mixes two shapes ("add this clock box to that whole-number box"), the golem first pours both into the more general shape, and only then computes. It never asks whether that is what you meant.

And the golem reads every order by a fixed table of ranks. It doesn't see the parentheses you had in mind, only the ones you wrote. Where you wrote none, the rank table decides which operation happens first.

In C++: the shapes are the fundamental types int, unsigned int, float/double and bool. "Pouring into the more general shape" is the implicit conversion of mixed expressions, the clock wrap-around is arithmetic modulo $2^B$ for unsigned integers, the mesh is the holes in the floating point range, and the rank table is precedence and associativity. If you master these four, the "types and values" task is pure routine.

2. How C++ reads an expression: precedence and associativity

The script's example (Code 3.1, p. 30) converts Celsius to Fahrenheit with 32 + 9 * celsius / 5. For 15 °C it prints 59, which is right ($32+27$). But how does C++ know not to compute $((32+9)\cdot15)/5$ like an old pocket calculator? Four rules, all from the script (p. 31–32):

Rule 1, precedence. Multiplicative operators *, /, % bind more strongly than additive operators +, -.

Rule 2, associativity. The arithmetic operators *, /, %, +, - are left associative: operators of the same precedence are evaluated from left to right.

Rule 3, arity. Unary +, - bind more strongly than the binary +, -, *, /. So -3 - 4 is (-3) - 4.

Rule 4, parentheses. Parentheses override everything: they are stronger than precedence and associativity.

So 32 + 9 * celsius / 5 means 32 + ((9 * celsius) / 5): rule 1 puts 9 * celsius / 5 together, rule 2 then does the * before the /. With these rules every expression gets exactly one way of putting in parentheses.

Attention (script p. 31)

C++ knows no commutativity or associativity laws. It never rewrites a * b / c as a * (b / c) because "it's the same in maths". It evaluates by the rules above, full stop. With integer division (section 3) the two really are different.

Expression trees

The parentheses define a tree (p. 32–33): each operator is a node, its operands hang below it, the leaves are literals and variables, and the root is the last operation. Computer scientists draw trees with the root on top:

The tree says: a node can only be evaluated after its children. It does not say which of two sibling subtrees goes first. In (a+b) * (a-b), C++ may compute a+b or a-b first; the order is not defined (p. 32–33). Normally that doesn't matter. It matters when a subexpression changes a variable that another one reads:

"Good" and "bad" expressions (p. 33). An expression is good if every valid evaluation order gives the same result. a * (a = 2) with a = 1 is bad: reading a first gives $1\cdot2=2$, assigning first gives $2\cdot2=4$.

Guideline: avoid modifying a variable that is used in the same expression more than once.

3. The arithmetic operators, and their surprises

Assignment is right associative

Unlike -, the assignment is right associative (p. 34): a = b = c means a = (b = c). The inner assignment's value is the new b, which is then stored in a. Useful for a = b = 0;. Unary - and + are right associative too, simply because their operand stands on the right.

Integer division: the lost remainder

If both operands are integers, / is integer division: it drops the remainder (rounds towards 0). So 5 / 2 is 2. This breaks a mathematical identity (script Example 3.1, p. 35):

#include <iostream>

int main() {
  const int celsius = 15;
  // 9 * 15 = 135, then 135 / 5 = 27: exact
  std::cout << 32 + 9 * celsius / 5 << "\n";
  // 9 / 5 = 1 (remainder lost!), 1 * 15 = 15
  std::cout << 32 + 9 / 5 * celsius << "\n";
  return 0;
}
59
47

Guideline (p. 35): watch out for potential loss of precision, and postpone operations with potential loss of precision, to avoid error escalation. Here: multiply first, divide last.

Modulo, and negative numbers

a % b is the remainder of the integer division: 5 % 2 is 1. Two rules pin down every case, also negative ones (p. 35):

Div-mod identity: (a / b) * b + a % b equals a.

Sign rule: (-a) / b equals -(a / b). Division rounds towards zero.

So -3 / 5 is 0 (because 3 / 5 is 0), and then the identity forces -3 % 5 = $-3 - 0\cdot5 = -3$. In mathematics, $-3 \bmod 5 = 2$. The script's fix, for $m>0$: (a % m + m) % m gives the mathematical result (here $(-3+5)\bmod5=2$).

Worked example 1: -7 / 2, -7 % 2, 7 % -2

  1. -7 / 2?
    Answer

    7 / 2 is 3, so by the sign rule -7 / 2 is −3 (towards zero, not −4).

  2. -7 % 2? Use the identity.
    Answer

    $-7 = (-3)\cdot2 + r$ gives $r=-1$. So -7 % 2 is −1. A practical consequence: the test "x % 2 == 1" for odd numbers fails for negative odd x. Test x % 2 != 0 instead.

  3. 7 % -2?
    Answer

    7 / -2 is −3 (towards zero), and $7 = (-3)(-2) + r$ gives $r = 1$. The remainder takes the sign of the left operand.

Increment and decrement

Arithmetic assignments (p. 36): a += b means a = a + b (but evaluates a once). The same exists for -=, *=, /=, %=.

4. Integers: int and unsigned int

The range of int

Every variable lives in memory with a fixed number of bits, so its type can only hold finitely many values (p. 37). With $B$ bits, int holds the $2^B$ integers

$$\{-2^{B-1},\ -2^{B-1}+1,\ \dots,\ -1,\ 0,\ 1,\ \dots,\ 2^{B-1}-1\}.$$

On almost every machine (and on Code Expert) $B=32$: from $-2147483648$ to $2147483647$, about $\pm 2.1$ billion. C++ only guarantees $B\ge16$.

Overflow (p. 38)

If an int computation leaves the range, that is undefined behavior: no guarantee, no error message. The script's power8 program prints $15^8 = -1732076671$. Know the rough size: $10^9$ fits, $10^{10}$ does not.

unsigned int: the clock

unsigned int holds the $2^B$ numbers $\{0, 1, \dots, 2^B-1\}$ (p. 38). Literals get the suffix u: 17u. All the arithmetic operators work. The big difference: unsigned over- and underflow are defined; the result is computed modulo $2^B$. So with $B=32$, 0u - 1u is $2^{32}-1 = 4294967295$. It is the clock arithmetic $\mathbb Z/2^{32}$ from Linear Algebra lesson 1.

Mixed expressions: int meets unsigned

If one operand is int and the other unsigned int, the result is unsigned int, the "more general" type, and the int operand is converted before computing (p. 38–39):

int value xbecomes the unsigned value
$x\ge0$$x$
$x<0$$x+2^B$

For example, −1 becomes $2^{32}-1$. The other way, int a = 3u; converts back and keeps the value as long as it fits.

Worked example 2: why the script says "avoid unsigned" (Example 4.4, p. 39)

#include <iostream>

int main() {
  unsigned int a = 10;
  int b = -110;
  int c = (a + b) / 10;  // what is c?
  std::cout << "c=" << c << "\n";
  return 0;
}
  1. What is the type of a + b, and what happens to b?
    Answer

    unsigned int. b = −110 is converted to $2^{32}-110 = 4294967186$.

  2. Finish the computation.
    Answer

    a + b $= 4294967196$ (that is $-100 + 2^{32}$, as an unsigned). / 10 is unsigned integer division: $429496719$. That fits into an int, so

    c=429496719

    instead of the −10 you'd expect. One unsigned variable silently turned the whole computation into clock arithmetic.

Guideline (p. 39): avoid unsigned integers unless you have specific reasons to use them. The C++ Core Guidelines (Sutter, Stroustrup) say the same. Use int.

5. Floating point numbers: float and double

With int only, 9 * celsius / 5 + 32 rounds silently. For 16 °C you'd expect 60.8, but get 60 (p. 40; the script uses 15 here, which happens to give exactly 59). For fractions we need float or double (p. 40–42):

  • float: about 7 significant digits, exponent up to about ±38.
  • double ("double precision"): about 15 digits, exponent up to about ±308. Use double by default.
  • The division / is the real division. There is no % for floating point numbers (it doesn't compile).

Literals: what type is a number?

A literal is a floating point literal if it has a decimal point and/or an exponent. By default it is a double; the suffix f makes it a float (p. 41):

Holes in the value range

The script's surprise (p. 42): read 1.1, 1.0 and 0.1 into floats and print n1 - n2 - d. Mathematically 0; the program prints 2.23517e-08. Not every decimal number can be stored exactly: floating point numbers have a huge range, but holes. 0.1 is one of the values that falls through the mesh. The consequence for now: never test floating point numbers with == unless you know the values are exact (like 0.25 or 2000). Why exactly is lesson 8 (number representations).

6. Logical values: bool

The type bool has two values, the literals false and true (p. 43). They come from the relational operators, which compare two arithmetic values and give a bool (an rvalue): <, <=, >, >=, == (equal), != (not equal). For example a % 3 == 1 is true for a = 4 (p. 44).

The binding ladder

To put parentheses into a mixed expression you need the ranks. The script's short version (p. 45–46), from strongest to weakest:

  1. unary operators: !, unary -, ++, --
  2. binary arithmetic: * / %, then + -
  3. relational: < <= > >=, then == !=
  4. logical: &&, then ||
  5. assignment =, +=, … (right associative)

Within a level, left to right (except unary operators and assignment). The script lumps all relational operators together; the full table on cppreference puts ==/!= one rank below </>, as listed here. You will rarely need that detail.

Script Example 4.8: 7 + x < y && y != 3 * z || ! b is ((7 + x) < y) && (y != (3 * z)) || (!b), and since && binds more strongly than ||: (((7 + x) < y) && (y != (3 * z))) || (!b). Don't be fooled by layout: a || b && c || d is a || (b && c) || d.

bool and int convert into each other

Inherited from C (p. 47–48): true becomes 1 and false becomes 0; any int ≠ 0 becomes true and 0 becomes false. So int a = true; gives 1 and bool b = 3; gives true. That is how 3 > (1 < true) even compiles: 1 < true is 1 < 1, false, which becomes 0 in 3 > 0, true. Using int instead of bool is legal but bad style.

Worked example 3: 8 > 4 > 2 > 1 (Code Expert Exercise 2, Task 2)

  1. Put in the parentheses.
    Answer

    Relational operators are left associative: ((8 > 4) > 2) > 1. It is not the mathematical chain $8>4>2>1$.

  2. Evaluate.
    Answer

    8 > 4 is true, which becomes 1 when compared with 2: 1 > 2 is false, becomes 0: 0 > 1 is false. Type bool. To say "a lies between 2 and 4" in C++, write 2 < a && a < 4.

De Morgan's rules

For all a, b (p. 48):

!(a && b) == (!a || !b)  and  !(a || b) == (!a && !b).

"Not (sunny and hot)" is "cloudy or cold". "Not (sunny or hot)" is "cloudy and cold". To negate, flip each part and swap AND with OR.

You'll use this every time you negate a loop condition (lesson 3). Check them with the truth table above: four rows each.

Short circuit evaluation

Short circuit (p. 48): && and || evaluate their left operand first. If that already decides the result (false for &&, true for ||), the right operand is not evaluated at all.

This is a guarantee you can build on (Example 4.11): x != 0 && z / x > y never divides by zero, because if x is 0 the right side is skipped. It also means side effects on the right may not happen: in true || ++k > 0, k is not incremented.

Completeness: three operators are enough

Are AND, OR and NOT enough to build every logical function of two inputs, for example XOR ("one of them, but not both")? Yes (p. 46–47):

Theorem (completeness, script Theorem 4.1, p. 46). Every binary logical operator can be expressed with the three operators $\wedge$, $\vee$ and $\neg$.

The idea. A function of two bools is just its truth table: four rows, four output bits. Build one tiny formula for each row that is true only in that row, then OR together the formulas of the rows where the function is true.

What the definitions force

First line: let $f$ be any function $\{0,1\}^2\to\{0,1\}$, written by its column $v$ of the truth table (rows $(x,y)=(0,0),(0,1),(1,0),(1,1)$). Last line: a formula in $x,y$ using only $\wedge,\vee,\neg$ that has the same column. The gap: one formula per row, and a way to combine them.

Proof. The four "row formulas" $\neg x\wedge\neg y$, $\neg x\wedge y$, $x\wedge\neg y$, $x\wedge y$ are each true in exactly one row: $(0,0)$, $(0,1)$, $(1,0)$, $(1,1)$ respectively. If the column $v$ of $f$ has at least one 1, let $F$ be the OR of the row formulas of the rows where $v$ is 1. In any row, $F$ is true iff one of its parts is true iff that row is one where $v$ is 1, so $F$ has column $v$. If $v=0000$, take $x\wedge\neg x$, which is always false. ∎

Example. XOR has column $0110$: true in rows $(0,1)$ and $(1,0)$. So $x\oplus y = (\neg x\wedge y)\vee(x\wedge\neg y)$. The script also gives $(x\vee y)\wedge\neg(x\wedge y)$; check that it has the same column.

How to reproduce this under exam pressure
  1. Write the truth table of the function (4 rows).
  2. For each row with output 1, write the AND of $x$ or $\neg x$ and $y$ or $\neg y$ matching that row.
  3. OR them together. (All zeros: $x\wedge\neg x$.)

In short: one AND per true row, OR them up. In C++: (!x && y) || (x && !y).

Remark 4.1 adds: by De Morgan, $x\vee y = \neg(\neg x\wedge\neg y)$, so AND and NOT alone are already enough.

7. The exam task: type and value in five steps

This is everything above, packed into one routine. Use it on every "give the C++ type and value" task, and whenever you're not sure what a line of your own code computes.

Type and value in five steps

  1. Where are the parentheses? Use the binding ladder: unary, then * / %, then + -, then relational, then &&, then ||, then =. Same level: left to right.
  2. What is the type of each leaf? Literals by the table in section 5 (5 int, 5u unsigned int, 5.0 and 1e3 double, 5.0f float); variables as declared.
  3. At each operator from the bottom up: which type, then which value? Arithmetic: if the operand types differ, convert to the more general one first: bool → int → unsigned int → float → double. Two integer operands: / is integer division. Relational and logical operators always give bool.
  4. Are there side effects? ++x uses the new value, x++ the old one. In exams each expression starts from the given initial values.
  5. Does && or || stop early? Left side first; if it decides, the right side is never evaluated (even a division by zero there is harmless).

Then write the type exactly: int, unsigned int, float, double, bool. A bool value is true or false; a double like 4.0 may be written 4.

Worked example 4: IFMP January 2018, task 1 (official exam, 9 points)

Give the C++ type and value of: (a) 8 + 5 / 3 (b) 1.0 * 0.1 == 0.1 * 1.0 (c) 1e1 * 2e2 (d) 5 / 2.0f + 5 / 2.0 (e) !false || true && false (f) 17 % 5u. Try all six first.

  1. (a) and (c): which division, which literal types?
    Answer

    (a) 8 + (5 / 3); 5 / 3 is integer division, 1. int, 9. (c) Both literals have an exponent, so both are double: $10\cdot200$. double, 2000.

  2. (d): what are the two halves?
    Answer

    (5 / 2.0f) + (5 / 2.0). Left: int with float gives float, 2.5f. Right: int with double gives double, 2.5. float plus double gives double. double, 5.

  3. (b): same numbers, different order. Is == safe here?
    Answer

    $1.0$ is exact, and multiplying by 1 changes nothing, so both sides are the same stored value of 0.1. bool, true. (The danger of == is rounding, and there is none here.)

  4. (e) and (f).
    Answer

    (e) (!false) || (true && false): the left side is already true, so short circuit stops. bool, true. (f) int with unsigned int: unsigned int, $17 \bmod 5 = $ 2.

Coding task 1: seconds to hours, minutes and seconds

The reverse of lesson 1's coding task 2. Read a number of seconds t (0 ≤ t < 86400) and print it as h:m:s, for example 3725 as 1:2:5.

What the contract forces (before any idea)
  • Given: one int t with $0\le t<86400$.
  • Must hold at the end: the line h:m:s with $t=3600h+60m+s$, $0\le m,s\le59$.
  • The gap to fill: split one number into "how many full hours", "how many full minutes", "what's left".

Try it yourself in the editor, then press Check.

#include <iostream>

int main() {
  // input: seconds since midnight
  int t;
  std::cin >> t;

  // computation
  int h = 0;   // replace these three lines
  int m = 0;
  int s = 0;

  // output
  std::cout << h << ":" << m << ":" << s << "\n";
  return 0;
}
  1. What goes in, what comes out?
    My answer

    In: one int t in [0, 86400). Out: three numbers separated by colons (no leading zeros needed).

  2. Examples by hand. 3725? 59? 86399?
    My answer

    3725: 3600 fits once, 125 left; 60 fits twice, 5 left: 1:2:5. 59: 0:0:59. 86399: 23:59:59.

  3. Steps in words. What did you do with "fits once, … left"?
    My answer

    "How often does 3600 fit" is integer division t / 3600; "what's left" is t % 3600. Then the same with 60. No magic step left.

  4. Edge case.
    My answer

    t = 0 gives 0:0:0. Negative t is excluded by the contract (it would give negative parts, since % keeps the sign).

  5. Code.

    My answer

    3725, 59, 0, 3600 (1:0:0), 86399. And lesson 1's program run on the output should give back the input.

Patterns used: input · compute · output / for "how often", % for "what's left" one named const per step

How to write this under exam pressure
  1. Largest unit first: h = t / 3600, rest = t % 3600.
  2. Then the next unit on the rest: m = rest / 60, s = rest % 60.
  3. Check with the identity $3600h+60m+s=t$ on one example.

In short: "divide for the count, modulo for the rest, unit by unit".

Coding task 2: equivalent resistance, rounded (Code Expert Exercise 2, Task 3)

Resistors R1 and R2 are in series, R3 and R4 are in series, and these two pairs are in parallel. Read four positive ints and print the equivalent resistance rounded to the nearest integer. Only int is allowed, and no if-statements. Physics: in series $R=R_a+R_b$; in parallel $R=\frac{R_aR_b}{R_a+R_b}$.

What the contract forces (before any idea)
  • Given: four positive ints $R_1,\dots,R_4$.
  • Must hold at the end: one number, $\frac{R_{12}R_{34}}{R_{12}+R_{34}}$ rounded to the nearest integer.
  • Allowed: int only, no if.
  • The gap to fill: rounding to nearest, when integer division always rounds down.

Try it yourself in the editor, then press Check.

#include <iostream>

int main() {
  // input
  int r1, r2, r3, r4;
  std::cin >> r1 >> r2 >> r3 >> r4;

  // computation (int only, no if)
  int r = 0;   // replace this line

  // output
  std::cout << r << "\n";
  return 0;
}
  1. What goes in, what comes out?
    My answer

    In: four positive ints. Out: $\frac{R_{12}R_{34}}{R_{12}+R_{34}}$ rounded to the nearest integer, where $R_{12}=R_1+R_2$, $R_{34}=R_3+R_4$.

  2. Examples by hand. R = 1, 1, 1, 1? And 1, 2, 3, 4?
    My answer

    $R_{12}=R_{34}=2$: $\frac{4}{4}=1$. And $R_{12}=3$, $R_{34}=7$: $\frac{21}{10}=2.1$, rounded 2. A case that must round up: $R_{12}=3$, $R_{34}=3$ (e.g. 1, 2, 1, 2): $\frac{9}{6}=1.5$, rounded 2.

  3. Steps in words. The magic step is "round to nearest". How do you do it with integer division, which always rounds down for positive numbers?
    Hint 1

    Rounding to nearest is the same as adding one half and then rounding down.

    Hint 2

    Write $\frac pq+\frac12$ as one fraction with denominator $q$.

    My answer

    Rounding $p/q$ to nearest is rounding $p/q + \tfrac12$ down. And $\frac pq+\frac12=\frac{p+q/2}{q}$. So compute (p + q / 2) / q. For odd $q$, q / 2 loses a half, which is fine: $p/q$ can then never be exactly halfway.

  4. Check the plan on the examples.
    My answer

    $p=21, q=10$: $(21+5)/10 = 2$ ✓. $p=9,q=6$: $(9+3)/6=2$ ✓. $p=4,q=4$: $(4+2)/4=1$ ✓.

  5. Code.
    My answer (written by StudyHub, compiled and tested)
    The golem's stepsWhat you write

    Read the four resistances.

    int r1, r2, r3, r4;
std::cin >> r1 >> r2 >> r3 >> r4;

    Each pair in series: just add.

    const int r12 = r1 + r2;
const int r34 = r3 + r4;

    The parallel formula as a fraction p over q, kept as two whole numbers.

    const int p = r12 * r34;
const int q = r12 + r34;

    Add half of q before dividing: that turns "round down" into "round to nearest".

    const int r = (p + q / 2) / q;
std::cout << r << "\n";
    The program in one piece
    #include <iostream>

int main() {
  // input
  int r1, r2, r3, r4;
  std::cin >> r1 >> r2 >> r3 >> r4;

  // computation
  const int r12 = r1 + r2;      // series
  const int r34 = r3 + r4;      // series
  const int p = r12 * r34;      // numerator
  const int q = r12 + r34;      // denominator
  // round p / q to nearest: add half of q first
  const int r = (p + q / 2) / q;

  // output
  std::cout << r << "\n";

  6. Tests.
    My answer

    1 1 1 1 → 1; 1 2 3 4 → 2; 1 2 1 2 → 2. Big values: $R_{12}R_{34}$ must stay below $2^{31}$, so resistances up to about 20000 each are safe. That is the overflow question from section 4 in practice.

Patterns used: input · compute · output round to nearest: (p + q/2) / q one named const per step

How to write this under exam pressure
  1. Keep the fraction as two ints p and q; never divide early.
  2. Round to nearest: (p + q / 2) / q (positive numbers only).
  3. Test one case that must round up (1.5 → 2) and one that must round down (2.1 → 2).
  4. Overflow: say in one sentence how big the inputs may be.

In short: "numerator, denominator, add half, divide last".

Worked examples: a mixed set before the exercises

Worked example 5: IFMP January 2016, task 1 (official exam)

With unsigned int u = 5; int i = -10; double d = 0.25; give type and value of (a) u == 4 * ++d (b) u / 3 * 2.0 + i (c) u - (--i)--.

  1. (a)
    Answer

    ++d makes d 1.25 and has that value; 4 * 1.25 is a double, 5. Then u == 5.0: u is converted to double. bool, true.

  2. (b) Careful with the first division.
    Answer

    ((u / 3) * 2.0) + i. u / 3 is unsigned integer division: 1. Then 1 * 2.0 = 2.0 (double), and 2.0 + (-10): i converted to double. double, −8. (Note: i is converted to double, not to unsigned, because double is more general.)

  3. (c) The hardest one: what is (--i)--?
    Answer

    --i makes i −11 and is i (an lvalue), so -- after it is allowed: post-decrement, value −11 (old value), i becomes −12. Then u - (-11): unsigned minus int gives unsigned int. −11 becomes $2^{32}-11$, and $5-(2^{32}-11) = 16 - 2^{32}$, which modulo $2^{32}$ is 16. Clock arithmetic gives the mathematically right answer here, because the true result 16 is in range.

Worked example 6: IFMP January 2017, task 1 (c) and (f) (official exam)

(c) 0 / 1 == 0 || 1 / 0 == 1 (f) 0.1f == 0.1

  1. (c) Does it divide by zero?
    Answer

    ((0 / 1) == 0) || ((1 / 0) == 1). The left side is 0 == 0, true, so short circuit skips the right side: no division by zero happens. bool, true.

  2. (f) Both are "0.1". Why can the answer be false?
    Answer

    0.1 falls into a hole. As a float it is rounded to about 7 digits, as a double to about 15 digits, and the two rounded values differ. The float is converted to double for the comparison, but the precision it lost doesn't come back. bool, false.

Exercise 2 (IFMP August 2017, task 1, without (c)) · 7.5 points

(a) (1 || 1) && !(1 && 1) (b) 1.0e2f / 2.0e3f (d) 1.0f == 1 (e) 10 % 4 * 5 (f) 15 / 2 / 5 * 2

Solution

Frame: the five steps of section 7: parentheses by the binding ladder, then for each operator the type, then the value.

(a) The ints 1 are converted to true: true && !true = true && false: bool, false. (It is XOR of 1 and 1, from the completeness section.)

(b) float / float: $100/2000$: float, 0.05. (d) 1 is converted to float, 1.0f == 1.0f, exact: bool, true.

(e) % and * have the same rank, left to right: (10 % 4) * 5 = 2 · 5: int, 10. (f) ((15 / 2) / 5) * 2 = (7 / 5) · 2 = 1 · 2: int, 2.

Exercise 3 (IFMP January 2015, task 1) · 6 points

With int x = 5; int y = 2; double z = 1.5; (each expression starting from these values): (a) x / y + z (b) ++y % --x / z (c) x++ * 6 > y * z * 10

Solution

Frame: the five steps, and each part starts again from the given values; for ++ and --, ask "old value or new value?".

(a) (x / y) + z = 2 + 1.5: double, 3.5.

(b) ((++y) % (--x)) / z = (3 % 4) / 1.5 = 3 / 1.5: double, 2.

(c) (x++ * 6) > ((y * z) * 10). x++ has the old value 5, so the left is 30; the right is 2 · 1.5 · 10 = 30. 30 > 30 is false: bool, false.

Exercise 4 (IFMP August 2015, task 1) · 6 points

With unsigned int u = 5; int i = -10; float f = 0.25f;: (a) f * 0.5 * 0.32e2 == u / 2 * 2 (b) u * -i * f (c) ++u - ++i + 10

Hint 1

In (b) and (c), find the first operator where an int meets the unsigned int. From there on, everything is computed modulo $2^{32}$.

Hint 2

For (c): $6 - (-9) = 15$ also holds modulo $2^{32}$, so you don't need the big number to get the final value.

Solution

Frame: the five steps, with one extra question at each operator: does an int meet an unsigned int here?

(a) Left: 0.25 · 0.5 · 32 = 4 (double, since 0.5 is a double). Right: (u / 2) * 2 = 2 · 2 = 4 (unsigned int). 4.0 == 4: bool, true.

(b) (u * (-i)) * f: -i is the int 10; u * 10 is unsigned int 50; 50 * f is float 12.5. float, 12.5.

(c) ((++u) - (++i)) + 10 = (6u − (−9)) + 10. Unsigned: −9 becomes $2^{32}-9$, and $6-(2^{32}-9) \equiv 15$, then +10: unsigned int, 25.

Exercise 5 (IFMP August 2016, task 2) · 6 points

With int n = 9; int f = 5; unsigned int u = 8; bool a = false; bool b = true;: (a) -n - ++f (b) u-7 == -1 (c) a || !b && !a || b

Hint 1

In (b), what type is u-7? What happens to −1 when it is compared with that type?

Solution

Frame: the five steps of section 7: parentheses by the binding ladder, then for each operator the type, then the value.

(a) (-n) - (++f) = −9 − 6: int, −15.

(b) (u - 7) == (-1). Left: unsigned 1. Right: −1 is converted to unsigned for the comparison: $2^{32}-1$. 1 == 4294967295 is false: bool, false. (A mathematician says true; the golem pours −1 into a clock box.)

(c) a || (!b && !a) || b = false || (false && true) || true: bool, true.

Exercise 6 (true or false, Code Expert Exercise 2, Task 2) · 4 points

With int a = 3;: (1) true || false && false (2) (true || false) && false (3) 3 > (1 < true) (4) 2 < a < 4

Solution

Frame: parentheses first (&& before ||, comparisons left to right), then evaluate.

(1) true: true || (false && false), and short circuit stops at true. (2) false: the parentheses force true && false. (3) true: 1 < 1 is false = 0, and 3 > 0. (4) true, but for the wrong reason: (2 < a) < 4 is 1 < 4. It would be true for every a, even a = 100. Write 2 < a && a < 4.

Summary: what to keep from lesson 2

  • Parentheses by the binding ladder; same rank left to right; assignment right to left. Only parentheses beat the ladder.
  • Two integers: / drops the remainder (towards 0); % follows from (a/b)*b + a%b == a. Divide last.
  • int: $[-2^{31}, 2^{31}-1]$, overflow is undefined. unsigned int: $[0, 2^{32}-1]$, computed modulo $2^{32}$. Mixed: the int becomes unsigned ($x+2^{32}$ if negative). Avoid unsigned.
  • double (15 digits) > float (7 digits) > integers. Literal types: 2, 2u, 2.0, 2e0, 2.0f. Holes: don't compare floats with ==.
  • bool: relational and logical operators; && before ||; De Morgan; short circuit; bool ↔ int (true is 1, nonzero is true).
  • Method: type and value in five steps (section 7).

For wonder: unsigned int is a ring (optional, 5 min)

The clock boxes are not a defect but a piece of algebra. unsigned int with + and * is exactly the ring $\mathbb Z/2^{32}$ from Linear Algebra lesson 1: every law you proved there holds, for every pair of values, with no exceptions. It is not a field, since 2 has no inverse (there's no $x$ with $2x\equiv1$). But every odd number has one. For example, $3\cdot2863311531 \equiv 1 \pmod{2^{32}}$, so in C++ 3u * 2863311531u is 1u. Compilers use exactly this trick to replace a slow division by a constant with a fast multiplication.
