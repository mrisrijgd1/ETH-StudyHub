Parentheses come from the binding ladder (unary, * / %, + -, relational, &&, ||, =). Two integers: / drops the remainder. Mixed types convert to the more general one. && and || stop early. Check yourself:

  2. How do you write "x is not between 1 and 9" with !, and without it?

1. The story: the golem turns back

Until today the golem read its scroll like a road: from the first line to the last, never stopping, never turning. That is a poor servant. A real recipe says "stir until it thickens" and "if the dough is sticky, add flour".

So the scroll-writers gave the golem two new kinds of order. A fork: "look at this yes-or-no box; if yes, take the left path, otherwise the right". And a loop marker: "look at the box; as long as it says yes, walk back to this mark and do the passage again". With forks and loop markers, ten lines of scroll can keep the golem busy for a million steps.

The danger came with the power. A loop marker whose box never turns to "no" sends the golem round and round forever, and no gatekeeper can warn you about every such scroll. The scroll-writer has to be able to say, for each loop, what changes every round, and why it eventually ends.

In C++: the fork is the selection statement (if, if-else, switch), the loop marker is an iteration statement (for, while, do), the yes-or-no box is the condition, and the round-and-round golem is an infinite loop. That no gatekeeper can catch all of them is the undecidability of the halting problem (script p. 52). Being able to argue termination yourself is a skill this lesson trains.

2. Selection: if and if-else

if (script p. 49): if (condition) statement. The condition is any expression convertible to bool; the statement is the body. The body runs if and only if the condition is true.

if-else (p. 49–50): if (condition) statement1 else statement2. If the condition is true, statement1 runs, otherwise statement2. Exactly one of the two.

#include <iostream>

int main() {
  int a;
  std::cin >> a;
  if (a % 2 == 0) {        // condition: a is even
    std::cout << "even";   // runs only if true
  } else {
    std::cout << "odd";    // runs only if false
  }
  std::cout << "\n";       // after the if: always
  return 0;
}
odd

(This test also works for negative odd a: -7 % 2 is −1, not 0. Testing a % 2 == 1 would fail for them, lesson 2.)

Blocks: always use braces

A block { statement1 statement2 … } groups several statements into one (p. 53). The body of an if or a loop is one statement, so if you want two, you need a block. The script's warning (p. 54):

for (int i = 1; i <= n; ++i)
    s += i;
    std::cout << "partial sum is " << s << "\n";

The indentation suggests both lines belong to the loop. The compiler ignores indentation: only s += i; is the body, and the output runs once, after the loop. Recommendation (p. 54): use a block in every selection and iteration statement, even for a single line. All code on this site does.

3. The for loop

for (script p. 50–51): for (init-statement; condition; expression) body.

  1. The init-statement runs once, when the loop is entered.
  2. The condition is evaluated. If it is false, the loop ends and the program continues after it.
  3. Otherwise the body runs,
  4. then the expression (usually the "progress", like ++i), and the loop goes back to step 2.

The script's example (Code 5.1, p. 51) sums $1+2+\dots+n$:

#include <iostream>

int main() {
  // input
  std::cout << "Compute the sum 1+...+n for n=? ";
  int n;
  std::cin >> n;
  // computation: s collects the sum
  int s = 0;                       // empty sum
  for (int i = 1; i <= n; ++i) {   // i = 1, 2, ..., n
    s += i;                        // add the next number
  }
  // output
  std::cout << "1+...+" << n << " = " << s << "\n";
  return 0;
}
Compute the sum 1+...+n for n=? 1+...+4 = 10

This is the accumulator pattern: a variable that starts at the neutral value (0 for sums, 1 for products) and collects one piece per round. Note that the condition is checked n + 1 times: n times true, once false. And i exists only inside the loop (section 6).

Termination, and the halting problem

Here ++i moves i towards making i <= n false; after $n$ rounds it is. That is the shape of every termination argument: something changes every round, in one direction, and the condition becomes false once it has gone far enough. Infinite loops are easy to write: for ( ; ; ); has an empty condition, which counts as true, and runs forever (p. 52). And they are impossible to detect in general:

Undecidability of the halting problem (script p. 52). There is no C++ program that can determine, for each C++ program P and each input I, whether P terminates on input I.

So correctness cannot in general be checked automatically. Writing loops that stop is our responsibility.

Worked example 1: the prime test loop (script p. 52–53)

A natural number $n\ge2$ is prime if no $d\in\{2,\dots,n-1\}$ divides it. The script's loop has an empty body (the null statement ;):

// PRE: n >= 2
int d;
for (d = 2; n % d != 0; ++d);   // find smallest divisor
if (n == d) {
  std::cout << n << " is prime";
} else {
  std::cout << n << " is divided by " << d;
}
  1. Trace it for $n=9$. What is printed?
    Answer

    d = 2: 9 % 2 = 1 ≠ 0, continue; d = 3: 9 % 3 = 0, the condition is false, stop. d = 3 ≠ 9, so it prints 9 is divided by 3.

  2. Why does the loop always stop for $n\ge2$?
    Answer

    d starts at 2 ≤ n and grows by 1 every round. At the latest when d == n, n % d is 0 and the condition is false. So at most $n-1$ rounds.

  3. What happens for $n=1$, and what does the script conclude?
    Answer

    $1 \bmod d = 1$ for every $d\ge2$, so the condition is never false: an infinite loop. The loop is only correct for $n\ge2$, so we write that down as a precondition (// PRE: n >= 2). Lesson 4 makes pre- and postconditions part of every function.

  4. Why is n == d at the end exactly the test for "prime"?
    Answer

    The loop stops at the smallest divisor $d\ge2$ of $n$. If that is $n$ itself, no $d$ in $\{2,\dots,n-1\}$ divides $n$: prime. Otherwise $d<n$ is a proper divisor.

4. Tracing loops: the exam method

The variable table from lesson 1, extended by one rule: write a row every time the condition is checked. That single habit prevents nearly every off-by-one error.

Loop output in five steps

  1. Which parts, in which order? for: init once, then condition → body → expression, repeat. while: condition → body, repeat. do: body → condition, repeat (the body runs at least once).
  2. What is my table? One column per variable, one for the condition, one for the output. A new row at every condition check.
  3. What exactly changes, and where? Look for changes everywhere: in the header, in the body, and inside the condition (--i > 1 changes i at every check). ++x vs x++ as in lesson 2.
  4. Do jumps or scopes change the flow? continue skips the rest of the body, but in a for the expression still runs. break leaves the loop at once. A variable declared in the body is created anew every round.
  5. Does it stop? Find what changes each round and check that it really reaches the stopping value. Warning signs: != with a step that jumps over the target, != with floating point values that aren't exact (0.1), unsigned values that can never be negative, a progress that goes the wrong way. If it can't stop, the answer is "infinite loop".

Worked example 2: IFMP January 2016, task 2 (c) (official exam, 2 points)

for (int i = 10; --i > 1; i--)
  std::cout << i << " ";
  1. Step 3: where does i change?
    Answer

    Twice per round: in the condition (--i, before the check) and in the expression (i--, after the body). So i drops by 2 per round, and the printed value is the one after the first decrement.

Worked example 3: IFMP January 2018, task 2 (a) and (c) (official exam)

(a) and (c): write the output, or "infinite loop".

// (a)
for (double d = 0.25; d != 16; d = 2*(d+1))
  std::cout << d << ", ";

// (c)
unsigned int n = 12;
while (n > 1) {
  std::cout << n << ", ";
  if (n % 2 == 0)
    n = n / 2;
  else
    n = 2 * n;
}
  1. (a): which values does d take? Is != safe here?
    Answer

    0.25, then $2(1.25)=2.5$, then $2(3.5)=7$, then $2\cdot8=16$: stop. All these values are exact in binary (quarters and halves), so d != 16 is reliable. Output: 0.25, 2.5, 7,

  2. (c): follow n.
    Answer

    12 → 6 → 3 (odd) → 6 → 3 → 6 → … n never gets below 3, the condition n > 1 stays true: infinite loop. (The program prints 12, 6, 3, 6, 3, … forever; the official answer is "infinite loop".) Step 5 of the method catches it: the progress isn't monotone.

5. while and do-while

while (p. 58): while (condition) statement. Evaluate the condition; while it is true, run the body and evaluate again. It is the same as for ( ; condition; ) statement.

do-while (p. 60): do statement while (condition); (note the semicolon). Run the body, then check; repeat while true. The body runs at least once.

Why three loops if one would do? Readability. The script's rule of thumb (p. 58):

situationloopscript example
a fixed number of rounds, a counter ("counting loop")forsum $1+\dots+n$
repeat while a condition holds; progress is not a simple counterwhileCollatz sequence
the body must run at least once before the check makes sensedothe calculator that reads until 0

The Collatz sequence (p. 58–59): from $n$, halve if even, otherwise go to $3n+1$; stop at 1. As a while loop it reads like its definition:

#include <iostream>

int main() {
  int n;
  std::cin >> n;              // PRE: n >= 1
  while (n != 1) {            // stop when 1 is reached
    if (n % 2 == 0) {
      n = n / 2;              // n even
    } else {
      n = 3 * n + 1;          // n odd
    }
    std::cout << n << " ";
  }
  std::cout << "\n";
  return 0;
}
16 8 4 2 1

Does this loop always stop? Nobody knows. That every start reaches 1 is the Collatz conjecture, open since 1937 (p. 59). Here the termination argument of section 3 is not just hard but unknown, which shows why no compiler can decide termination for you.

The calculator (p. 60): it must read a number before it can test it, so do fits.

int summand;          // next summand
int sum = 0;          // current sum
do {
  std::cout << "next number = ? ";
  std::cin >> summand;
  sum += summand;
  std::cout << "sum = " << sum << "\n";
} while (summand != 0);

6. Scope: where a variable is visible

Why does this not compile (p. 55)?

int s = 0;
for (int i = 0; i < 10; ++i)
  s += i;
std::cout << i;   // error: 'i' was not declared

Scope (Gültigkeitsbereich, script p. 55–57). A variable is visible from its declaration to the end of the scope it is declared in. Scopes are made by blocks { }, function bodies and control statements; the i of a for header lives only in that loop. Scopes nest: from inside you can see outward, never inward.

Shadowing. Declaring a variable with the same name in an inner scope is allowed; inside, the new one shadows the outer one. In the same scope it is an error ("redeclaration").

Local variables are created anew each time their declaration is reached, and destroyed at the end of their scope.

Worked example 4: two scope traps (script p. 56–57)

// (a)
int i = 2;
for (int i = 0; i < 5; ++i)
  std::cout << i;
std::cout << i;

// (b)
int i = 5;
for (int j = 0; j < 5; ++j) {
  std::cout << ++i;
  int k = 2;
  std::cout << --k;
}
  1. (a): which i does each output print?
    Answer

    Inside the loop the header's i shadows the outer one: 01234. After the loop the outer i is visible again, untouched: 2. Output 012342.

  2. (b): the tempting answer is 6 1, 7 0, 8 −1, … Why is it wrong?
    Answer

    k is declared in the body, so every round makes a new k with value 2, and --k is always 1. i is declared outside and keeps counting. Output: 61718191101 (6 1 7 1 8 1 9 1 10 1, without spaces).

7. Jump statements: break and continue

break; leaves the innermost enclosing loop (or switch) immediately (p. 61).

continue; skips the rest of the body of the current round and goes on with the next round: in a for loop to the expression, then the condition; in while and do to the condition (p. 63).

The script improves the calculator with them (p. 61–63). The 0 that ends the input shouldn't be added; and negative numbers should be ignored:

#include <iostream>

int main() {
  int summand;
  int sum = 0;
  while (true) {                     // leave via break
    std::cout << "next number = ? ";
    std::cin >> summand;
    if (summand < 0) continue;       // ignore negatives
    if (summand == 0) break;         // end of input
    sum += summand;
    std::cout << "sum = " << sum << "\n";
  }
  return 0;
}
next number = ? sum = 3
next number = ? next number = ? sum = 7
next number = ?

while (true) with a conditional break in the middle is a common pattern: the loop-and-a-half. The script's balance (p. 64): jumps can make code shorter and avoid nested ifs, but they complicate the control flow, so use them only where they make it simpler. Its own example (p. 67–68), printing the odd numbers below 100, gets better twice by removing the jump:

// with continue: works, but roundabout
for (int i = 0; i < 100; ++i) {
  if (i % 2 == 0) { continue; }
  std::cout << i << "\n";
}
// best: loop only over what you need
for (int i = 1; i < 100; i += 2) {
  std::cout << i << "\n";
}

The script's final word on style (p. 68): the most important goal is code that is easy to understand for others and for your future self.

Control flow (p. 64–67): every control statement can be drawn as a flow diagram, and underneath all of them are just two things, a conditional jump (if) and an unconditional jump (goto). The structured statements exist for us humans.

8. The switch statement

For a case distinction over many values of one integer, switch is clearer than a chain of ifs (p. 68–70). The script's grades example (6: "Excellent … You passed!", 5 and 4: "You passed!", 3: "Close, but … You failed!", 2 and 1: "You failed!", otherwise "Error!"):

#include <iostream>

int main() {
  int grade;
  std::cin >> grade;
  switch (grade) {
    case 6: std::cout << "Excellent ... ";  // falls through
    case 5:                                 // falls through
    case 4: std::cout << "You passed!";
      break;                                // leave switch
    case 3: std::cout << "Close, but ... "; // falls through
    case 2:
    case 1: std::cout << "You failed!";
      break;
    default: std::cout << "Error!";         // all other values
  }
  std::cout << "\n";
  return 0;
}
Close, but ... You failed!

switch (p. 69): the expression (of an integral type) is evaluated and the program jumps to the matching case label, or to default if none matches (or past the switch if there is no default). From there it runs on through the following cases until a break or the end: this is called fall-through. Forgetting a break is the classic switch bug, so the script recommends turning on the compiler warning for it.

Coding task 1: digit sum

Read a non-negative int n and print the sum of its decimal digits. Example: 4096 gives 19.

What the contract forces (before any idea)
  • Given: one int n with $n\ge0$.
  • Must hold at the end: one number printed, the sum of n's decimal digits.
  • The gap to fill: the computer has no "digits", only the number. How do you get them out one by one?

Try it yourself in the editor, then press Check.

#include <iostream>

int main() {
  // input. PRE: n >= 0
  int n;
  std::cin >> n;

  // computation
  int sum = 0;
  // your loop here

  // output
  std::cout << sum << "\n";
  return 0;
}
  1. What goes in, what comes out?
    My answer

    In: an int n ≥ 0 (precondition). Out: one number, the digit sum, and a line break.

  2. Examples by hand. 4096? 7? 0?
    My answer

    4 + 0 + 9 + 6 = 19; 7; 0. Watch yourself: you read the digits off left to right, but the computer can't "see" digits at all. It only has the number.

  3. Steps in words. How do you get one digit out of a number with the operators you know?
    My answer

    The last digit is n % 10 (4096 % 10 = 6). Removing it is n / 10 (409). Repeat until nothing is left (n becomes 0). Add each digit to an accumulator.

  4. Edge case, and does it stop?
    My answer

    n = 0: the loop while (n > 0) doesn't run, the sum stays 0 ✓. Termination: n ≥ 0 and n /= 10 makes a positive n strictly smaller, so n reaches 0 after as many rounds as it has digits.

  5. Which pattern? Code.
    My answer (written by StudyHub, compiled and tested)
    The golem's stepsWhat you write

    Read n. Start an empty sum box.

    int n;
std::cin >> n;
int sum = 0;

    As long as something is left: take the last digit, add it, and cut it off.

}

    Nothing left: write the sum.

    The program in one piece
    #include <iostream>

int main() {
  // input. PRE: n >= 0
  int n;
  std::cin >> n;

  // computation: peel off the last digit
  int sum = 0;              // accumulator
  while (n > 0) {
    sum += n % 10;          // last digit

  }

  // output

  return 0;
}
    19

    A while fits: we don't know the number of rounds in advance (it's the number of digits).

  6. Tests.
    My answer

    4096 → 19, 7 → 7, 0 → 0, 10 → 1, 2147483647 → 46 (the largest int).

Patterns used: accumulator peel off the last digit: % 10, / 10

How to write this under exam pressure
  1. Accumulator first: int sum = 0; before the loop.
  2. Loop while something is left: while (n > 0).
  3. Body in two lines: use the last digit (n % 10), then remove it (n /= 10).
  4. Check n = 0 by hand: the loop must not run.

In short: "start at 0, peel digits until nothing is left".

Your turn: the coding ladder

  1. What goes in, what comes out?
    My answer

    In: n ≥ 2. Out: the primes whose product is n, smallest first, each as often as it divides n.

  2. By hand: 24, and 90. What do you do, exactly?
    My answer

    24: 2 divides it → write 2, go on with 12; 2 divides → 2, 6; 2 → 2, 3; 2 doesn't divide 3 → try 3: divides → 3, 1. Done: 2 2 2 3. 90: 2 → 45; 2 no, 3 → 15; 3 → 5; 3 no, 4 no, 5 → 1. 2 3 3 5.

  3. Steps in words.
    Hint 1

    Look at your hand computation for 24: after printing a 2, did you move on to 3, or try 2 again?

    Hint 2

    You were done when the number left over was 1.

    My answer

    Keep a candidate d, starting at 2. As long as there's something left to factor (n > 1): if d divides n, print d and divide it out (and try the same d again); otherwise move on to d + 1.

  4. Check: does it ever print a non-prime, like 4?
    My answer

    No: when d reaches 4, every factor 2 has already been divided out, so 4 can't divide n any more. The same argument works for every composite d. And it stops: each round either n shrinks (and stays ≥ 1) or d grows, and d never passes n while n > 1, because n itself is a divisor.

  5. Fill the gaps.
    Answer (official solution, checked by compiling)

    Frame: the loop runs while there is something left to factor; the if asks "is d a factor?".

    The golem's stepsWhat you write

    (1) Keep going while something other than 1 is left.

    n > 1

    (2) Does the candidate divide what is left?

    n % d == 0

    (3) Yes: it was printed; divide it out and keep the same candidate.

    n /= d

    (4) No: try the next candidate.

    ++d

    The official solution also accepts d <= n for (1).

    The program in one piece
    #include <iostream>

// PRE: n >= 2
// POST: outputs the prime factorization of n
void prime_factors (unsigned int n)
{
  unsigned int d = 2;      // candidate divisor
  while (n > 1) {          // something left to factor
    if (n % d == 0) {      // d divides n:
      std::cout << d << " ";
      n /= d;              // divide it out, keep d
    } else {
      ++d;                 // next candidate
    }
  }
}

int main() {
  unsigned int n;
  std::cin >> n;
  prime_factors(n);
  std::cout << "\n";
  return 0;
}

Coding task 3: Fibonacci primes (Code Expert Exercise 3, Task 2a)

The Fibonacci numbers are 1, 1, 2, 3, 5, 8, 13, …; each is the sum of the two before. Read an int m and print, one per line, every Fibonacci number in $[2, m]$ that is prime, then Found N Fibonacci primes. Only int.

You'll need these

The prime test of Worked example 1 (search for the smallest divisor), and overflow from lesson 2.

What the contract forces (before any idea)
  • Given: one int m, any value.
  • Must hold at the end: every prime Fibonacci number in $[2,m]$ printed once, in order, then the count line word for word.
  • Allowed: int only, so no number may ever pass $2^{31}-1$.
  • The gap to fill: two jobs in one, and a stop that never overflows.

  1. What goes in, what comes out?
    My answer

    In: an int m (could be anything up to the largest int). Out: the qualifying numbers, one per line, then the count line.

  2. By hand, m = 20.
    My answer

    Fibonacci numbers in [2, 20]: 2, 3, 5, 8, 13. Primes among them: 2, 3, 5, 13. Output those, then Found 4 Fibonacci primes.

  3. Steps in words. Two jobs are hiding in one task. Which?
    My answer

    Job 1: walk through the Fibonacci numbers up to m (keep the last two, a and b; next is a + b). Job 2: for each one ≥ 2, test whether it is prime (the search-until-found pattern of Worked example 1), and count. So: an outer loop over Fibonacci numbers, an inner loop for the prime test.

  4. Edge cases. m < 2? m = the largest int?
    Hint 1

    For m = 2147483647, what is the first Fibonacci number above m? Can an int hold it?

    Hint 2

    Test "would the next one be too big?" before adding, and rearrange the test so it only subtracts.

    My answer

    m < 2: nothing printed, then Found 0 Fibonacci primes. m = 2147483647: the largest Fibonacci number below it is 1836311903; computing the next one, 2971215073, would overflow (undefined behavior, lesson 2). So stop before adding when the next number would exceed m: a + b > m is the same as a > m - b, and m - b can't overflow. The prime test has the same danger with d * d <= k; d <= k / d avoids it.

  5. Code.
    My answer (written by StudyHub, compiled and tested)
    The golem's stepsWhat you write

    Keep the last two Fibonacci numbers in two boxes.

    int a = 1;  // previous
int b = 1;  // current

    Before stepping on: would the next one pass m? Then stop. The test only subtracts, so it can't overflow.

    if (a > m - b) break;
const int next = a + b;
a = b;
b = next;

    Job 2: search for the smallest divisor of b, up to its square root.

    int d = 2;
while (d <= b / d && b % d != 0) {
  ++d;
}

    The search ran out without finding one: b is prime. Write it and count it.

    if (d > b / d) {
  std::cout << b << "\n";
  ++count;
}
    The program in one piece
    #include <iostream>

int main() {
  int m;
  std::cin >> m;

  int count = 0;
  int a = 1;              // previous Fibonacci number
  int b = 1;              // current Fibonacci number
  while (true) {
    // next number: stop before it exceeds m
    // (a > m - b means a + b > m, without overflow)
    if (a > m - b) break;
    const int next = a + b;
    a = b;
    b = next;             // b runs through 2, 3, 5, ...

    // prime test: search the smallest divisor
    // up to the square root (d <= b / d)
    int d = 2;
    while (d <= b / d && b % d != 0) {
      ++d;
    }
    if (d > b / d) {      // no divisor found: prime
      std::cout << b << "\n";
      ++count;
    }
  }
  std::cout << "Found " << count
            << " Fibonacci primes\n";
  return 0;
}

How to write this under exam pressure

Exercise 3 (IFMP August 2017, task 2 (a), (b)) · 4 points

// (a)
double d = 2.0;
do {
  std::cout << (--d)++;
} while (d < 2.0);

// (b)
double d = 1.5;
while (d != 1) {
  std::cout << d << " ";
  d -= 0.1;
}
Hint 1

In (a), --d returns d itself (an lvalue), so (--d)++ is allowed. Which value does the postfix ++ hand to the output?

Hint 2

In (b), is 0.1 one of the values a double can store exactly (lesson 2, holes)?

Solution

Frame: a trace table with one row at every condition check (section 4).

(a) --d makes d 1.0 and is d; (…)++ prints the old value 1 and makes d 2.0 again. The check 2.0 < 2.0 is false. Output 1.

(b) Infinite loop. 0.1 is not exact in binary, so after five subtractions d is very close to 1 but not equal, and != stays true; d keeps falling forever. Rule: never stop a floating point loop with != unless every value is exact; use d > 1.05 or count with an int.

Exercise 5 (loop mix-up, Code Expert Exercise 4, Task 1) · 3 points

int f = 1;
if (n > 0) {
  do {
    f = f * n;
    --n;
  } while (n > 0);
}
std::cout << f;

(a) What does it compute? (b) Which loop fits best, and why? (c) Rewrite it.

Solution

Frame: what is known before the loop starts: a fixed number of rounds (for), an unknown number (while), or at least one round (do)?

(a) $n!$ for $n\ge1$, and 1 for $n\le0$. (b) The if exists only because do would run once even for n ≤ 0: a sign that do is the wrong loop. A fixed count from n down to 1 is a counting loop: for. (c) Written by StudyHub:

int f = 1;
for (int i = n; i > 0; --i) {
  f *= i;            // f = n * (n-1) * ... * 1
}
std::cout << f;

For n ≤ 0 the condition is false at once and f stays 1, so the if disappears.

Summary: what to keep from lesson 3

  • if/else: exactly one branch. Always use braces; indentation means nothing to the compiler.
  • for (init; cond; expr): init once, then cond → body → expr. while: cond → body. do: body → cond (at least once).
  • Termination: name what changes each round and why the condition becomes false. The halting problem says no tool can do this for you in general.
  • Scope: visible from declaration to the end of the block; inner names shadow outer ones; locals in a loop body are new every round.
  • break leaves the loop; continue skips to the next round (in a for, via the expression). switch falls through until break.
  • Method: loop output in five steps, a row at every condition check. Patterns: accumulator, peel off a digit, search until found, loop-and-a-half.

For wonder: a three-line loop nobody understands (optional, 5 min)

The Collatz loop of section 5 is three lines long. It has been run for every starting value up to about $2.95\cdot10^{20}$, and every one reaches 1. Yet nobody can prove that all of them do. Paul Erdős said that mathematics "is not yet ready for such problems". Try 27 (script p. 59): it climbs as high as 9232 and takes 111 steps before it comes down to 1. A loop's behaviour can be far deeper than its code.
