Recap of lesson 4 (5 minutes)

A call evaluates the arguments, makes a new table with copies of them, runs the body, and the first return hands one value back. PRE says what must hold at the call, POST what holds afterwards. Check yourself:

  1. After int f(int x) { x = 2 * x; return x; } and int a = 5; int b = f(a);, what are a and b?
    Answer

    a = 5, b = 10. f doubled its own copy of 5; main's a was never reached (pass by value). This lesson shows how to write f so that it can change a, when we want it to.

  2. What is wrong with int g(int n) { if (n > 0) return 1; }?
    Answer

1. The story: the golem's row of jars

Until now, every box in the golem's workshop had its own name: a, b, count. Then the surveyors from the gardens next door brought a request: "Keep the rainfall of every day of the year." Three hundred and sixty-five names? Nobody wanted to write them.

So the jar-maker built a shelf: one long row of jars, all of the same shape, standing side by side, with one name for the whole row: rain. The jars carry numbers, and the first one is number 0. "Bring me jar 41 of rain," says the scroll, and the golem walks straight to it: it knows where the shelf starts and how wide one jar is, so it never has to count along the row. But the shelf ends somewhere. Ask for jar 365 of a 365-jar shelf, and the golem grabs at whatever stands behind it. The gatekeeper does not stop it.

The second novelty was smaller: a name tag. A tag can be stuck onto a box that already exists, and from then on the box has two names. Whatever you pour in under one name, you find under the other. With tags, a spell in the book of spells can finally reach a box back in the caller's workshop: instead of a copy, the caller hands over a tag for its own box.

In C++: the shelf is a vector, its jar numbers are indices starting at 0, walking straight to a jar is random access, grabbing behind the shelf is an out of bounds access (undefined behaviour), and the name tag is a reference. The script's motivation for vectors (p. 97): "we can iterate over numbers … often, however, we have to iterate over data".

2. A vector: many boxes under one name

Vector type (script p. 97): std::vector<T>, where T is the type of the elements, the base type. You need #include <vector>. The four ways to make one (p. 100):

  • std::vector<int> fivezeros = std::vector<int>(5); five elements, all 0;
  • std::vector<int> fivetwos = std::vector<int>(5, 2); five elements, all 2 (in general std::vector<T>(n, e): n elements with value e);
  • std::vector<int> countdown = {5, 4, 3, 2, 1}; the values listed;
  • std::vector<int> empty; no elements at all.

Index operator (p. 99): for a vector vec and an integer expression with value i ≥ 0, vec[i] is an L-value of type T: the element number i, counting from 0. Being an L-value, it can be read and written: vec[2] = vec[0] + 1;

Why is vec[i] fast, however long the vector? The elements lie side by side in one block of memory (p. 98–99). If the vector starts at address p and one element takes s memory cells, element i sits at address $p + s\cdot i$: one multiplication and one addition, whatever i is. That is random access.

The script introduces vectors with an old algorithm for the primes below n, the Sieve of Eratosthenes (p. 97): write down 2, 3, …, n − 1; take the smallest number not crossed out, it is prime; cross out all its proper multiples; repeat. A vector of bools remembers what is crossed out. Code 7.1, p. 98 (with the input prompt shortened):

#include <iostream>
#include <vector>   // standard containers with vector functionality

int main() {
  int n;
  std::cin >> n;
  // crossed_out[0], ..., crossed_out[n-1], all initialised to false
  std::vector<bool> crossed_out = std::vector<bool>(n, false);

  std::cout << "Prime numbers in {2,...," << n - 1 << "}:\n";
  for (int i = 2; i < n; ++i) {
    if (!crossed_out[i]) {          // i is prime
      std::cout << i << " ";
      for (int m = 2 * i; m < n; m += i) {
        crossed_out[m] = true;      // cross out all proper multiples of i
      }
    }
  }
  std::cout << "\n";
  return 0;
}

3. Staying inside the vector: size, push_back, at

Out of bounds (p. 100): accessing an element outside the valid indices 0, …, size − 1 is undefined behaviour. Checking is "the sole responsibility of the programmer (us)". The script's Example 7.5:

std::vector<int> vec = std::vector<int>(10);
for (int i = 0; i <= 10; ++i)
  vec[i] = 30;   // Undefined behavior: accessing vec[10]

Undefined means anything may happen: the program may seem to work, print rubbish, or crash with exit code −11 (segmentation fault) on Code Expert.

Three member functions you'll use all the time (p. 100):

  • v.size(): the number of elements.
  • v.push_back(x): appends x at the end; the vector grows by one. This is how you fill a vector whose length you don't know in advance.
  • v.at(i): like v[i], but with a bound check at run time: an index outside the vector stops the program with an error instead of silently reading or writing somewhere else.
#include <iostream>
#include <vector>

int main() {
  std::vector<int> v;          // empty
  v.push_back(4);
  v.push_back(8);
  v.push_back(15);             // v is now {4, 8, 15}
  std::cout << v.size() << " " << v[0] << " " << v.at(2) << "\n";
  v[1] = v[0] + v[2];          // v[1] is an L-value: we can write it
  for (int i = 0; i < std::ssize(v); ++i) {
    std::cout << v[i] << " ";
  }
  std::cout << "\n";
  return 0;
}
3 4 15
4 19 15

Change v.at(2) to v.at(3) and press Run: the program stops with std::out_of_range. With v[3] instead, nothing tells you.

The size is unsigned: the trap of section 7.2.1

v.size() has type std::size_t, an unsigned integer type (p. 101). From lesson 2 you know what happens when it meets an int: the int is converted to unsigned, and unsigned arithmetic never goes below 0.

Worked example 2: an endless loop (script Example 7.8, p. 101)

std::vector<int> a {1, 2, 3};
for (int x = 0; a.size() - x - 1 >= 0; ++x) {
  std::cout << x;
}
  1. What type does a.size() - x - 1 have?
    Answer

    a.size() is unsigned, so x and 1 are converted to unsigned (lesson 2, mixed expressions), and the whole expression is unsigned.

  2. What happens for x = 3?
    Answer

    3 − 3 − 1 would be −1, but in unsigned arithmetic it wraps around to the largest value, $2^{64}-1$ for a 64-bit size_t. An unsigned value is always ≥ 0, so the condition is always true: the loop never ends. (With the option -Wextra, the compiler warns: "comparison of unsigned expression in '>= 0' is always true".)

  3. How does the script fix it?
    Answer

    With std::ssize(a), the signed size (C++20, p. 101–102): std::ssize(a) - x - 1 >= 0 is an int-like expression and becomes false at x = 3. Without C++20, int(a.size()) does the same.

The rule we follow

Recommendation (p. 102): to avoid mixed integer expressions, use std::ssize(v) for the size of a vector v. Our loop over a vector is always:

for (int i = 0; i < std::ssize(v); ++i) {
  ... v[i] ...
}

Three checks before you press Run: the first index is 0; the condition is <, not <=; every v[…] inside has an index between 0 and std::ssize(v) - 1, also in the first and last round.

4. Vectors of vectors: tables and matrices

The base type of a vector may itself be a vector (p. 103). std::vector<std::vector<int>> m; is a vector whose elements are vectors of int: a table, one inner vector per row. The two common ways to make one:

// the 3-by-3 identity matrix, written out
std::vector<std::vector<int>> id = {
  {1, 0, 0},
  {0, 1, 0},
  {0, 0, 1}
};
// rows-by-cols, every entry 1
std::vector<std::vector<int>> m =
  std::vector<std::vector<int>>(rows, std::vector<int>(cols, 1));

m[i] is row i (a whole std::vector<int>), m[i][j] is the entry in row i, column j. m.size() is the number of rows, m[0].size() the number of columns of row 0 (p. 103). In memory, the rows lie one after the other (Figure 7.1, p. 104); "rows first" is just the way we choose to think about it.

Walking a table needs two nested loops, the outer one over the rows, the inner one over the columns. The script's example sums the lower triangle of a square matrix, the entries below the diagonal (p. 104):

#include <iostream>
#include <vector>

// POST: returns the sum of all entries below the diagonal of matrix
int lower_triangle_sum(const std::vector<std::vector<int>>& matrix) {
  int sum = 0;
  for (int row = 0; row < std::ssize(matrix); ++row) {
    for (int column = 0; column < row; ++column) {   // only left of the diagonal
      sum += matrix[row][column];
    }
  }
  return sum;
}

int main() {
  std::vector<std::vector<int>> m = {
    {1, 2, 3},
    {4, 5, 6},
    {7, 8, 9}
  };
  std::cout << lower_triangle_sum(m) << "\n";   // 4 + 7 + 8
  return 0;
}
19

The script writes row < matrix.size(); we write std::ssize by the rule of section 3. The parameter type const std::vector<…>& is explained in section 8: it means "read the caller's matrix without copying it".

Two more things from section 7.3:

  • Rows of different lengths are allowed (p. 105). The script's cantons example has rows of 8, 4 and 6 names; cantons[1].size() is 4. Then m[0].size() is not the length of every row: loop with std::ssize(m[row]) in the inner loop.
  • Shorter type names (p. 105–106). A type alias using imatrix = std::vector<std::vector<int>>; lets you write imatrix everywhere. And auto m = std::vector<std::vector<int>>(rows, std::vector<int>(cols, 1)); lets the compiler deduce the type from the right-hand side. auto is still a fixed type known at compile time, not Python's "any type"; use it only where the type is obvious.

5. References: a second name for a box

Here is the problem lesson 4 left open. This swap does nothing for the caller (script Example 8.1, p. 107):

#include <iostream>

void swap(int x, int y) {   // x and y are copies
  int t = x;
  x = y;
  y = t;
}

int main() {
  int a = 2;
  int b = 1;
  swap(a, b);
  std::cout << a << " " << b << "\n";   // still 2 1
  return 0;
}
2 1

The swapping inside works perfectly, but on copies. Now change two characters, int to int& (Example 8.2, p. 107):

#include <iostream>

// POST: values of x and y are exchanged
void swap(int& x, int& y) {   // x and y are other names for a and b
  int t = x;
  x = y;
  y = t;
}

int main() {
  int a = 2;
  int b = 1;
  swap(a, b);
  std::cout << a << " " << b << "\n";
  return 0;
}
1 2

Reference type (p. 108): T&, read "T-reference", where T is the underlying type. A T& has the same values and operations as a T, but initialisation and assignment work differently:

  • A reference must be initialised with an L-value, and it becomes an alias of it: another name for the same object.
  • From then on, every use of the reference, assignment included, acts on that object. A reference cannot be moved to another object later.

Internally, a reference is stored as the address of its object (p. 108).

The script's example (Example 8.3, p. 108):

#include <iostream>

int main() {
  int anakin_skywalker = 9;
  int& darth_vader = anakin_skywalker;   // alias: a second name, no new box
  darth_vader = 22;
  std::cout << anakin_skywalker << "\n";
  return 0;
}
22

What the gatekeeper refuses (p. 108):

int& darth_vader = anakin_skywalker; // ok
int& j;        // error: j must be an alias of something
int& k = 5;    // error: the literal 5 has no address

6. Pass by reference

A reference parameter is initialised, at the call, with the call argument. So the parameter becomes a second name for the caller's variable (p. 108–109):

Pass by reference (p. 109): the formal parameter has reference type and is initialised with the address of the call argument (an L-value); it becomes an alias.

Pass by value (the default): the formal parameter is not a reference; it is initialised with the value of the call argument (an R-value) and becomes a copy.

Consequence: the argument for a reference parameter must be an L-value. swap(a, b) is fine; swap(a, 3) and swap(a, b + 1) don't compile.

The five steps of lesson 4 need one change, in step 2:

A call with references, in five steps

  1. What are the arguments? For a value parameter: the value. For a reference parameter: which variable (it must be one; a value like 5 or a + 1 is refused).
  2. What is the new table? Start a new table for the call. A value parameter gets its own row with a copy. A reference parameter gets no row of its own: write its name as a second label next to the caller's variable, for example x → main's a.
  3. What does the body do? Trace the body. Every read or write of a reference parameter goes to the caller's variable, in the caller's table.
  4. Which return is reached? As before.
  5. What stays? Cross out the new table: the copies are gone, and so are the second labels. Every change made through a reference stays in the caller's table.

7. Return by reference, and a dangling reference

A function can also return a reference (p. 109–110). Then the call itself is an L-value: it can stand on the left of =, or be passed to another reference parameter. The script's inc (Example 8.6, p. 110) behaves exactly like ++x:

int& inc(int& i) {
  i = i + 1;
  return i;          // returns the caller's variable itself, not a copy
}
// inc(inc(x)) increments x twice

A more useful example: reading a vector with "wrap-around" indices, so that index 4 of a 4-element vector means index 0 again (Examples 8.7–8.10, p. 110–111). With return type int you could only read; with int& you can also write:

#include <iostream>
#include <vector>

// PRE:  vec is not empty, index >= 0
// POST: returns (a reference to) the element at index % size of vec
int& wrap_at(std::vector<int>& vec, int index) {
  return vec[index % std::ssize(vec)];
}

int main() {
  std::vector<int> v = {0, 1, 2, 3};
  std::cout << wrap_at(v, 2) << " " << wrap_at(v, 6) << "\n";   // both v[2]
  wrap_at(v, 6) = 6;               // allowed: the call is an L-value
  std::cout << wrap_at(v, 2) << "\n";
  return 0;
}
2 2
6

With return type int, the line wrap_at(v, 6) = 6; is refused: "lvalue required as left operand of assignment" (p. 111).

The danger (p. 111): what is wrong here?

int& foo(int i) {
  return i;          // i is foo's own copy: it dies at the return
}
int k = 3;
int& j = foo(k);     // j is an alias of a "zombie"
std::cout << j;      // undefined behavior!

Reference guideline (p. 111): when a reference is created, the object it refers to must stay alive at least as long as the reference itself. So never return a reference to a local variable or to a value parameter. Returning a reference to something the caller handed in by reference (like vec[…] in wrap_at) is fine.

8. Const references: read without copying

Pass by reference has a second use besides changing the argument: it avoids copying (p. 112). A vector passed by value is copied element by element at every call; a reference is just an address. But a plain reference allows changes, and so it refuses a const argument (Examples 8.12–8.14, p. 112):

double average(std::vector<double>& values);   // may change values?

const std::vector<double> temperatures = {0.9, 1.3, 5.1};
std::cout << average(temperatures);           // compiler error

The compiler cannot know that average happens not to change the vector, and neither can we without reading its body. The fix is one more word (Example 8.15, p. 113):

#include <iostream>
#include <vector>

// PRE:  values is not empty
// POST: returns the average of the elements of values
double average(const std::vector<double>& values) {
  double sum = 0;
  for (int i = 0; i < std::ssize(values); ++i) {
    sum += values[i];
  }
  return sum / std::ssize(values);
}

int main() {
  const std::vector<double> temperatures =
    {0.9, 1.3, 5.1, 9.1, 13.2, 17.1, 18.8, 18.6, 14.7, 10.6, 5.2, 1.8};
  std::cout << average(temperatures) << "\n";
  return 0;
}
9.7

Const reference (p. 113): const T&, read as (const T)&. It promises that the function will not change the object, and the compiler checks the promise: a line like values[0] = 0; in average is refused. A const T& may even be initialised with an R-value such as 5 or a + b; the compiler then makes a temporary object that lives long enough.

Rule (pass by read-only reference, p. 113): if possible, declare function argument types that are not fundamental types as const T&. It is both efficient and safe.

Which parameter type? Three questions

  1. Must the function change the caller's variable? Then T&. The POST then says what happens to it, for example "values of x and y are exchanged".
  2. Otherwise: is T a fundamental type (int, unsigned int, bool, double, …)? Then plain T: a copy is as cheap as an address.
  3. Otherwise (a vector, and later strings and structs): const T&.

Read a POST with this in mind: "returns …" alone means nothing is changed; "sets …", "increases …", "is sorted" means a T&.

    My answer

  2. By hand: 3 1 2. Which comparisons put it in order?
    My answer

    Compare a and b: 3 > 1, swap → 1 3 2. Compare b and c: 3 > 2, swap → 1 2 3. Now the largest is surely in c. Compare a and b once more: 1 < 2, nothing. Done.

  3. Why the third comparison? Find an input where it is needed.
    My answer

    2 3 1: a, b in order; b > c, swap → 2 1 3. Now the 1 moved into b, but a = 2 is larger: the third comparison swaps → 1 2 3. After the first two steps only the largest is surely in place; the third orders the other two.

  4. Write it.
    Answer (written by StudyHub, checked by compiling)

    Frame: three compare-and-swap steps: (a, b), (b, c), (a, b). Each swap goes through references to main's variables.

    The golem's stepsWhat you write

    The swap spell: keep x in a helper, pour y into x, the helper into y. x and y are tags on the caller's boxes.

    int t = x;
x = y;
y = t;

    Push the largest to the right: compare a, b, then b, c.

    if (a > b) swap(a, b);
if (b > c) swap(b, c);

    if (a > b) swap(a, b);

// PRE:  n >= 0

imatrix read_matrix(int n) {
  imatrix m = imatrix(n, std::vector<int>(n, 0));   // right size first

    }
  }
  return true;                           // none found

In this program, each of the placeholders A, B and H is replaced, independently, by int or int&. That gives 8 combinations. For each one, what is the output?

#include <iostream>

void foo (A a, B b)
{
  H h = a;
  a = b;
  b = h;
}

int main()
{
  int a = 2;
  int b = 3;
  foo (a, b);
  std::cout << a << b;

}

    Answer

  2. Take A = int, B = int. Which H gives which output?

    Both parameters are copies: nothing foo does reaches main, whatever H is. Both cases print 23.

  3. Take A = int&, B = int&, H = int. Trace it.
    Answer

    a and b are main's variables. h = 2 (a copy). a = b: main's a = 3. b = h: main's b = 2. A real swap: 32.

  4. Now the same with H = int&. What changes?
    Answer

    h is a second name for a, which is main's a. a = b: main's a = 3, and so h is 3 too. b = h: main's b = 3. Output 33: the "helper" was no helper, because it was not a box of its own.

  5. Fill the table for all 8 cases. Use the five steps of section 6: a reference is a label on an existing box.
    Answer
    ABHoutput
    intintint23
    intintint&23
    intint&int22
    intint&int&23
    int&intint33

Worked example 5: a vector by value, by reference, by const reference (written by StudyHub)

#include <iostream>
#include <vector>

void add_one_copy(std::vector<int> v) {        // v is a copy
  for (int i = 0; i < std::ssize(v); ++i) ++v[i];
}

void add_one(std::vector<int>& v) {            // v is the caller's vector
  for (int i = 0; i < std::ssize(v); ++i) ++v[i];
}

int sum(const std::vector<int>& v) {           // read only, no copy
  int s = 0;
  for (int i = 0; i < std::ssize(v); ++i) s += v[i];
  return s;
}

int main() {
  std::vector<int> a = {1, 2, 3};
  add_one_copy(a);
  std::cout << sum(a) << " ";
  add_one(a);
  add_one(a);
  std::cout << sum(a) << "\n";
  return 0;
}
  1. What does add_one_copy(a) change in main?
    Answer

    Nothing. A vector parameter without & is a full copy (three elements copied), and the copy is changed and then dies. Vectors are passed by value like ints, unless you write &.

  2. What is printed?
    Answer

    First sum: 1 + 2 + 3 = 6. Then two calls of add_one on main's vector: {3, 4, 5}, sum 12. Output 6 12.

  3. Which of the three functions could you call with a const std::vector<int>?
    Answer

    add_one_copy (a copy of a const vector is fine) and sum. Not add_one: a plain reference to a const object is refused, it would allow changes.

Exercise 1 (IFMP August 2015, task 9, official exam) · 6 points

Consider this program, which calls a function foo. What is its output for each of the three variants of foo (2 points each)?

int main()
{
  int a = 0;
  int b = 1;
  for (int i=0; i<5; ++i) {
    b = foo (a, b);
    std::cout << b << " ";
  }
  return 0;
}
// (a)
int foo (int& a, int b) { a += b; return a; }
// (b)
int foo (int a, int b)  { a += b; return a; }
// (c)
int foo (int a, int& b) { a += b; return a; }
Solution

Frame: the five steps of section 6, five times; for each variant ask first which of main's variables foo can change.

(a) foo's a is main's a. Round 1: a = 0 + 1 = 1, b = 1. Round 2: a = 1 + 1 = 2, b = 2. Round 3: a = 4, b = 4. Then 8, 16. Output 1 2 4 8 16 (official).

(b) Both are copies: main's a stays 0, so foo returns 0 + b = b = 1 every time. Output 1 1 1 1 1 (official).

(c) foo's b is main's b, but foo only reads it. a is a copy of main's a = 0, so foo returns 0 + 1 = 1, and main stores 1 in b. Output 1 1 1 1 1 (official). Only the written parameter matters: in (c) the reference is never written.

round(a) a, b(b) a, b(c) a, b
11, 10, 10, 1
22, 20, 10, 1
34, 40, 10, 1
48, 80, 10, 1
516, 160, 10, 1

main's a and b after each round.

Exercise 2 (argument types; (a) and (d) from IFMP January 2016, task 8, official exam) · 8 points

Provide the matching argument types (2 points each). The POST decides.

// (a) POST: increases the value of the variable balance by amount and
//           returns the new value of balance
float top_up (____ balance, ____ amount);

// (b) POST: returns the average of all values in the nonempty vector v
double average (____ v);

// (c) POST: the vector v of integers is sorted in increasing order
void sort (____ v);

// (d) POST: returns whether the natural number n is prime. If not,
//           factor is set to a proper divisor of n
bool is_prime (____ n, ____ factor);

(b) and (c) are our vector versions; the exam used pointer ranges there (lesson 12).

Solution

Frame: the three questions of section 8: does the POST change it? Is it fundamental?

(a) float top_up (float& balance, float amount); (official). "Increases the value of the variable balance": the caller's variable changes, so a reference; amount is only read and fundamental, so a value.

(b) double average (const std::vector<double>& v); Read only, and not fundamental. (A plain std::vector<double> works too but copies; 1 point.)

(c) void sort (std::vector<int>& v); "Is sorted": the caller's vector changes.

(d) bool is_prime (unsigned int n, unsigned int& factor); (official). "Natural number": unsigned int. "factor is set": a reference, so the function can hand back a second result besides the bool.

Exercise 3 (const and reference types, in the style of Code Expert Exercise 6, Task 1) · 5 points

For each function: does it compile? If yes, is its behaviour well defined? If yes, give its postcondition. 1 point per function. Written by StudyHub.

int f1(const int& i) { return i + 1; }

int f2(const int& i) { return ++i; }

int f3(int& i) { i = 2 * i; return i; }

int& f4() { int x = 5; return x; }

// PRE: v is not empty
int& f5(std::vector<int>& v) { return v[std::ssize(v) - 1]; }
Hint 1

For each function, ask two questions: does the body write to something declared const? Does a returned reference point to something that dies at the return?

Hint 2

Exactly one function doesn't compile and exactly one is undefined. Section 7 has the "zombie".

Solution

Frame: const references refuse writes (section 8); a returned reference must outlive the call (section 7); otherwise read the body for the POST.

f1: compiles, well defined. POST: returns i + 1 (i is unchanged).

f2: does not compile: ++i writes to a const int& ("increment of read-only reference").

f3: compiles, well defined. POST: doubles i and returns its new value.

f4: compiles (with a warning), but undefined: it returns a reference to the local variable x, which dies at the return.

f5: compiles, well defined under the PRE. POST: returns a reference to the last element of v (so f5(v) = 0; sets it to 0). Fine, because v is the caller's vector and outlives the call.

Exercise 4 (three vector bugs) · 3 points

Each snippet has a bug. Say what goes wrong and fix it (1 point each). Written by StudyHub.

std::vector<int> v = {4, 8, 15, 16, 23, 42};

// (1) print all elements
for (int i = 1; i <= std::ssize(v); ++i) std::cout << v[i] << " ";

// (2) sum of all elements except the last one; v may be empty
int s = 0;
for (int i = 0; i < v.size() - 1; ++i) s += v[i];

// (3) a vector holding 7
std::vector<int> w;
w[0] = 7;
Solution

Frame: the three checks of the rule in section 3: start at 0, use <, every index between 0 and size − 1.

(1) It skips v[0] and reads v[6], out of bounds: undefined behaviour. Fix: for (int i = 0; i < std::ssize(v); ++i).

(2) For an empty v, v.size() - 1 is unsigned and wraps around to a huge number: the loop reads far outside v. Fix: i < std::ssize(v) - 1, which is −1 for an empty vector.

(3) w is empty, so w[0] doesn't exist: undefined behaviour. Fix: w.push_back(7); or std::vector<int> w = {7};.

Exercise 5 (true or false) · 4 points

  1. int& r = 5; compiles.
  2. After int a = 1, b = 2; int& r = a; r = b;, r is an alias of b.
  3. A function with a const std::vector<int>& parameter can be called with a const std::vector<int>.
  4. v.at(i) with an index outside the vector is undefined behaviour.
Solution

Frame: each statement is about one rule of sections 3, 5 or 8; find it, then decide.

1. False: a reference must be initialised with an L-value; the literal 5 has no address (p. 108). 2. False: a reference can't be moved to another object; r = b assigns b's value to a. Now a = 2, and r is still an alias of a. 3. True (p. 113). 4. False: at checks the index and stops the program with an error (p. 100). It is v[i] that is undefined.

Summary: what to keep from lesson 5

  • std::vector<T>: (n), (n, e), {…}, empty. v[i] is an L-value, i from 0 to size − 1. Anything else is undefined behaviour; v.at(i) checks.
  • v.push_back(x) appends, v.size() is unsigned: loop with std::ssize(v).
  • A matrix is a vector of rows: std::vector<std::vector<int>>(rows, std::vector<int>(cols, 0)), m[i][j], two nested loops. using gives a short name.
  • T& is a second name for an existing L-value. Assignment through it changes that object; it can't be moved to another one.
  • Pass by reference lets a function change the caller's variable; return by reference makes the call an L-value. Never return a reference to a local variable.
  • const T& reads without copying and is checked by the compiler: use it for vectors you only read.
  • Methods: the ssize rule; a call with references in five steps; which parameter type in three questions.

For wonder: the man who measured the Earth (optional, 5 min)

Eratosthenes of Cyrene, whose sieve opened this lesson, was head of the great Library of Alexandria around 240 BC. He heard that at noon on midsummer day, in the town of Syene far to the south, the sun shone straight down a deep well. In Alexandria at the same moment, a vertical stick cast a short shadow: the sun stood about 7.2 degrees, one fiftieth of a full circle, away from straight overhead. So the distance from Alexandria to Syene had to be one fiftieth of the Earth's circumference. His result, about 250 000 stadia, is within a few percent of the true 40 000 km, depending on which length of the stadion he used. The same man also drew one of the first maps with lines of latitude, and invented the word "geography". The sieve is more than 2200 years old and still one of the fastest ways to list all primes up to a few million.
