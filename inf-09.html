1. The story: the golem glues boxes together

The golem's boxes hold one thing each: one whole number, one letter, one measurement. But the merchants of the town keep asking for things that come in pairs. A price of "two thirds of a silver piece" is two numbers, top and bottom. A place on the map is three numbers. A townsperson has a name, an age and a master.

So the scribes invent the glued box. A label on the lid says what it is, rational, and inside are two small boxes with their own labels, n and d. The glued box goes everywhere a single box goes: you can copy it, hand it to a helper, get one back.

But the golem is literal. Asked to add two glued boxes, it says: "I know how to add numbers. Nobody told me how to add these." So the scribes write it a page for each sign: here is what + means for rationals, here is what == means, here is how to write one on the wall. From then on, the golem reads r + s and turns to the right page.

In C++: the glued box is a struct, the small boxes inside are its member variables, and the pages for the signs are operator overloads. The script's goal (p. 149): a type rational that you can read with std::cin >> r, add with r + s and print with std::cout << t, exactly like an int.

2. Declaring a struct (script 12.1)

A struct introduces a new type T with a fixed list of member variables (p. 149):

struct T {
  T1 name1;
  T2 name2;
  // ...
  Tn namen;
};

Its value range is the Cartesian product $T_1 \times \dots \times T_n$ (p. 150): a value of T is one value for each member. For an object t of type T, t.name1 is its first member: this is member access. Don't forget the semicolon after the closing brace.

The script's main example, a rational number $n/d$ (p. 150):

struct rational {
  int n;
  int d; // INV: d != 0
};

Not every pair of ints is a valid rational: the denominator must not be 0. A condition that must always hold for the members is an invariant, written as a comment // INV:. For now we just assume it; lesson 10 shows how to enforce it.

Members can have any type, also another struct or std::string, and they don't have to have the same type (p. 150–151):

struct rational_vector_3 {
  rational x;
  rational y;
  rational z;
};

struct extended_int {
  // represents value if is_positive == true and -value otherwise
  unsigned int value;
  bool is_positive;
};

For rational_vector_3 v;, the numerator of the second component is v.y.n: member access chains from left to right.

A copy is a new, independent object: changing t later doesn't touch s. That is the same as for int and std::vector.

4. Structs as function arguments (script 12.4)

Structs can be parameters and return values, like fundamental types (p. 152). Adding two rationals, with $\frac{a_n}{a_d} + \frac{b_n}{b_d} = \frac{a_n b_d + a_d b_n}{a_d b_d}$:

rational add(rational a, rational b) {
  rational result;
  result.n = a.n * b.d + a.d * b.n;
  result.d = a.d * b.d;
  return result;
}

The arguments are passed by value: a and b are copies. To avoid the copies, write rational add(const rational& a, const rational& b). The takeaway (p. 153): you work with structs exactly as with fundamental types or vectors, with the same trade-offs, copy or not, const or not. For two ints, copying is cheap; for a struct with a long std::string inside, a const reference saves work.

5. Function overloading (script 12.5.1)

A function is identified by its signature: its name and the number and types of its parameters, without the return type (p. 153). So several functions may have the same name, as long as their parameter lists differ. The compiler chooses the version that fits the arguments "best".

double sq(double x) { ... }           // f1
int sq(int x) { ... }                 // f2
int pow(int b, int e) { ... }         // f3
int pow(int e) { return pow(2, e); }  // f4

sq(3) calls f2, sq(1.414) calls f1, pow(2) calls f4 (one argument), pow(3, 3) calls f3.

Two rules of thumb for "best": an exact match wins; and a small type that is promoted to a bigger one of the same kind (float → double, char → int) beats a conversion between kinds. The script doesn't go into details; these two cover the exam cases.

Worked example 2: which sq?

With f1 and f2 from above:

  1. sq(2.5f)?
    Answer

    No exact match for float. float → double is a promotion, float → int a conversion: f1, result 6.25.

  2. sq('a')?
    Answer

    char → int is a promotion: f2, 97 · 97 = 9409.

  3. Can you add double sq(int x) next to f2?
    Answer

    No: the signature sq(int) is the same, only the return type differs. The compiler reports an error ("ambiguating new declaration"). Here are f1 and f2 in action, with a note which one runs:

6. Operator overloading (script 12.5.2–12.5.4)

Operators are functions with a special name and a special way of calling them (p. 153). a + b calls a function named operator+ with arguments a and b; for strings you could even write operator+(x, y) directly. To make + work for rational, we add one more overload of operator+ (p. 154):

// POST: return value is the sum of a and b
rational operator+(rational a, rational b) {
  rational result;
  result.n = a.n * b.d + a.d * b.n;
  result.d = a.d * b.d;
  return result;
}

The same works for -, *, /. The unary minus has the same name operator- but one parameter: another overload.

// POST: return value is -a
rational operator-(rational a) {
  a.n = -a.n;
  return a;
}

Changing a here is fine: a is a copy, and we return it.

Arithmetic assignment r += s calls operator+= (p. 154–155). It must change its left operand, so the left parameter must be a reference. By C++ convention an assignment also has a value: it returns a reference to the left side, which allows chains like r += s += t.

// POST: assigns the sum a + b to a
rational& operator+=(rational& a, rational b) {
  a = a + b;
  return a;
}

Writing an operator overload in five steps

  1. What is the name? operator followed by the symbol: operator+, operator==, operator<<.
  2. How many parameters, in which order? One per operand, the left operand first. Binary a - b: two. Unary -a: one. 2 * v: first a double, then the vector.
  3. Does it change an operand? Then that parameter is a reference (+=: the left one; >>: the variable read into; << and >>: the stream). The others by value or by const reference.
  4. What does it return? A new value (by value) for + - * / and unary minus; bool for == and !=; a reference to the left operand for +=; a reference to the stream for << and >>.
  5. Can I reuse one I already have? += via +, != via ==, binary minus via plus and unary minus. Less code, fewer bugs.

Worked example 3: the += bug (script p. 155)

A first attempt passes both operands by value:

void operator+=(rational a, rational b) {
  a = a + b;
}
  1. What does rational r = {2, 3}; rational s = {3, 4}; r += s; followed by printing r give?
    Answer

    2 / 3 (p. 155): a is a copy of r; the sum 17/12 lands in the copy, which disappears when the function returns. r is unchanged. It compiles without any warning.

  2. Which step of the method was missed?
    Answer

    Step 3: += changes its left operand, so rational& a. With that, r becomes 17/12.

  3. With the correct version, trace r = {3, 1}; s = {2, 1}; t = {1, 1}; r += s += t;.
    Answer

    Assignments bind from the right: first s += t, s = (2 · 1 + 1 · 1)/(1 · 1) = 3/1, and the call returns s itself. Then r += s, r = (3 + 3)/1 = 6 / 1 (p. 156). The script calls such code "beautiful", sarcastically.

7. Comparison, output and input (script 12.5.5–12.5.6)

Comparison. r == s for two structs doesn't compile: "no match for 'operator=='" (p. 156). C++ doesn't know when two structs are equal, and member-wise comparison would be wrong here: 2/3 and 4/6 are the same number with different members. So we say what equality means, by cross-multiplying:

// POST: returns true iff a and b represent the same rational number
bool operator==(rational a, rational b) {
  return a.n * b.d == a.d * b.n;
}

Output. std::cout << r calls operator<<(std::cout, r). The left operand has type std::ostream, an output stream. Writing to it changes it, so it is passed by reference (p. 157). A first version returning void works for std::cout << r, but not for std::cout << r << " and " << s, which is

operator<<(operator<<(operator<<(std::cout, r), " and "), s)

The inner call must return the stream, so that the next call can write to it. Hence (p. 158):

// POST: r has been written to out
std::ostream& operator<<(std::ostream& out, rational r) {
  return out << r.n << " / " << r.d;
}

out << r.n << " / " << r.d itself returns out, so we return that directly.

Input. std::cin >> r calls operator>>(std::cin, r). Reading changes the stream (the read characters are gone) and changes r: both by reference. It also returns the stream, for chains like std::cin >> r >> s (p. 158):

// PRE:  in starts with a rational number of the form "n/d"
// POST: r has been read from in
std::istream& operator>>(std::istream& in, rational& r) {
  char c; // separating character, e.g. '/'
  return in >> r.n >> c >> r.d;
}

Now the script's goal program works (p. 159):

#include <iostream>

struct rational {
  int n;
  int d; // INV: d != 0
};

rational operator+(rational a, rational b) {
  rational result;
  result.n = a.n * b.d + a.d * b.n;
  result.d = a.d * b.d;
  return result;
}

std::ostream& operator<<(std::ostream& out, rational r) {
  return out << r.n << " / " << r.d;
}

std::istream& operator>>(std::istream& in, rational& r) {
  char c;
  return in >> r.n >> c >> r.d;
}

int main() {
  rational r;
  rational s;
  std::cin >> r >> s;
  std::cout << "sum is " << r + s << ".\n";
  return 0;
}
sum is 17 / 12.

Worked example 4: why << must return the stream

  1. Write std::cout << r << "\n"; as nested function calls.
    Answer

    operator<<(operator<<(std::cout, r), "\n"). The inner call is our overload; the outer one is the standard one for text.

  2. If our overload returned void, what would the outer call receive?
    Answer

    Nothing: operator<<(void, "\n") makes no sense, and the compiler rejects the line (p. 157). With std::ostream&, the inner call hands back std::cout itself.

  3. Why std::ostream& and not std::ostream as return type?
    Answer

    A stream can't be copied (there is only one console), and we want the next output to go to the very same stream. A reference is that same stream under another name.

8. The open problem: invariants (script 12.6)

Our rational now behaves like a built-in type. One problem remains (p. 159): nothing stops anyone from breaking the invariant.

rational r;
r.n = 1;
r.d = 1;
// ... much later ...
r.d--;      // now d == 0: r is no longer a rational number

Every member is open to everyone. The struct can't defend itself. Lesson 10 introduces classes with private members, which solve exactly this.

  1. The five steps for operator+.
    My answer

    Name operator+; two parameters, left first; changes nothing, so by value; returns a new rational; nothing to reuse yet.

  2. The formula, and a check of the invariant.
    My answer

    n = a.n · b.d + a.d · b.n, d = a.d · b.d. Since a.d ≠ 0 and b.d ≠ 0, also d ≠ 0: the sum keeps the invariant.

  3. Why not a.n == b.n && a.d == b.d?
    My answer

    That says 2/3 ≠ 4/6. Same value means $a_n/a_d = b_n/b_d$; multiply both sides by $a_d b_d \ne 0$: $a_n b_d = a_d b_n$. Only integers, no division, no rounding.

Coding task 2: vectors in space (after IFMP January 2016, task 6, 8 points)

The exam declared a 3D vector type and asked for scalar multiplication (3 points) and output in the format (x, y, z) (5 points); 2 * v + 3 * w with v = (1, 2, 3) and w = (3, 4, 5) must print (11, 16, 21). The exam's struct stores an array and has constructors (lessons 10 and 14); here it has three members. You write all three operators.

You'll need these

Aggregate initialization (section 3), the operator method, and the output operator of section 7.

What the contract forces (before any idea)
  • Given: two vectors v, w and a real number s.
  • Must hold at the end: $v + w = (v_1 + w_1, v_2 + w_2, v_3 + w_3)$, $s v = (s v_1, s v_2, s v_3)$, and the output is exactly (x, y, z) with a comma and a space between the numbers.
  • The gap to fill: the parameter order of 2 * v, and the exact output format.

Coding task 3: a clock that ticks (after the Informatik exam summer 2010, task 5)

The summer 2010 exam had a clock with hours, minutes and seconds, a function tick() for one second, and an output operator in the format h:m:s without leading zeros (1:2:20 is fine). There it was a class; here it is a struct with a free function.

You'll need these

A reference parameter that changes the caller's variable (lesson 5), % (lesson 2), and the output operator of section 7.

What the contract forces (before any idea)
  • Given: a time with h < 24, m < 60, s < 60 (the invariant).
  • Must hold at the end: after tick(t), t is one second later, still satisfying the invariant; after 23:59:59 comes 0:0:0.
  • The gap to fill: when does a carry go to the minutes, when to the hours?

  unsigned int m; // INV: m < 60

    My answer

    tick must change the caller's clock. With clock_time t it would tick a copy, exactly the += bug of worked example 3.

  2. When is there a carry?

  3. Does the invariant still hold after tick?

    Yes: every member that reaches its limit is reset to 0 at once, and % 24 keeps h below 24.

Coding task 4: who is the king? (after the Informatik exam summer 2011, task 6, 20 points)

On the planet Plato, every resident has exactly one master, who is a resident too; only kings have no master, and there are several kings. The exam asked (a) for a struct storing a resident's initials, age in years, and the index of their master, −1 for a king (10 points); and (b) for a function that finds the index of the king of a given resident, or −1 if that resident is a king (10 points). There were no cycles. The exam used an array; we use a vector.

You'll need these

A vector of structs and member access through an index, people[i].master; a while loop that follows a chain (like the 3n + 1 loop of lesson 3); passing a vector by const reference (lesson 5).

What the contract forces (before any idea)
  • Given: the residents, read only; a valid index; no cycles.
  • Must hold at the end: the index of the resident at the top of the chain of masters, or −1 if the resident has no master.
  • The gap to fill: why does following masters end? And the special case for kings.

};

//       or -1 if people[index] is a king

  return -1; // todo

  int n;
  std::cin >> n;
  std::vector<resident> people(n);
  for (int i = 0; i < n; ++i)
    std::cin >> people[i].initials >> people[i].age >> people[i].master;
  int index;
  std::cin >> index;
  std::cout << find_king(people, index) << "\n";
  return 0;
}
  1. Why do the initials fit a std::string, and why is master an int, not unsigned int?
    My answer

    A string holds any number of letters (two char members would also do). master must hold −1, so it must be signed.

  2. How do you walk up the chain?
    My answer

    Start at i = index; while people[i].master != -1, set i = people[i].master. When the loop stops, i has no master: it is the king.

  3. Why does the loop end, and what about kings?
    My answer

    No cycles: every step goes to a new resident, and there are only n, so after at most n − 1 steps we reach someone without a master. If people[index] is itself a king, the loop wouldn't run and would return index; the POST wants −1, so check that first.

  4. Write it.
    Answer (written by StudyHub, checked by compiling)

    Frame: special case "is a king"; then follow the master links until there is none.

    The golem's stepsWhat you write

    If this resident has no master, they are a king themselves: the answer is −1.

    if (people[index].master == -1) return -1;

    Otherwise, keep walking to the master's door until you meet someone who answers to nobody.

  i = people[i].master;
return i;

Exercise 3 (Informatik exam winter 2009/10, task 5, old exam) · 23 points

For a computer game, points in space are given as

struct point {
  double x, y, z;
};

(a) Implement double distance(const point& p): the distance of p from the origin. Tip: std::sqrt. (7 points)

(b) Propose a struct line to represent straight lines in space. A line need not have a unique representation, but every object of type line must determine a unique line. If necessary, define an invariant (// INV:). (8 points)

(c) Based on your proposal, implement line line_through(const point& a, const point& b), the line through a and b. Make sure the invariant holds, either by a precondition or by tests in the function. (8 points)

Hint 1

From linear algebra: a line is a point plus all multiples of a direction, $\{p + t\,d : t \in \mathbb{R}\}$. Which d must be forbidden?

Hint 2

For (c), the direction from a to b is b − a. When is it forbidden?

Solution

Frame: (a) member access and a formula; (b) members that describe the object, plus an invariant that rules out the invalid combinations; (c) a PRE that guarantees the invariant. No official solution exists; written by StudyHub, checked by compiling.

#include <cmath>

// POST: returns the distance of p from the origin
double distance(const point& p) {
  return std::sqrt(p.x * p.x + p.y * p.y + p.z * p.z);
}

// represents the line {p + t * d : t real}
struct line {
  point p;  // a point on the line
  point d;  // the direction
  // INV: d is not (0, 0, 0)
};

// PRE:  a and b are different points
// POST: returns the line through a and b
line line_through(const point& a, const point& b) {
  line result;
  result.p = a;
  result.d = {b.x - a.x, b.y - a.y, b.z - a.z};
  return result;
}

Why the invariant: with d = (0, 0, 0), $\{p + t\,d\}$ is the single point p, not a line. Every other d gives exactly one line (different p, d can give the same line: allowed). In (c), a ≠ b is exactly what makes b − a ≠ 0. Points: (a) correct formula and return; (b) two points members, the meaning written down, the invariant; (c) the PRE, the direction b − a, returning the struct.

Exercise 4 (output chains, after script p. 157) · 3 points

Someone writes void operator<<(std::ostream& out, rational r) { out << r.n << "/" << r.d; }. Which of these lines compile? (1 point each)

(a) std::cout << r;   (b) std::cout << r << "\n";   (c) std::cout << "r = " << r;

Solution

(a) Compiles: one call, its result is unused. (b) Error: operator<<(operator<<(std::cout, r), "\n") would write to void. (c) Compiles: operator<<(operator<<(std::cout, "r = "), r): the inner standard call returns the stream, and ours is outermost. Return std::ostream& and all three work.

Summary: what to keep from lesson 9

  • A struct groups member variables into a new type; its values are tuples. Access members with t.name. Write invariants as // INV:.
  • T t; leaves fundamental members undefined; T t = {…}; fills them in order; copies and assignments are member-wise.
  • Structs are passed and returned like int: by value (copy) or by (const) reference.
  • Overloading: same name, different parameter lists. The signature is name + parameter types; the return type doesn't count.
  • Operators are functions named operator+ etc. Left operand = first parameter. + - * / return a new value; += takes the left operand by reference and returns it; == returns bool and must compare values.
  • << and >> take the stream by reference and return it, so that chains work; >> also takes the target by reference.
  • Open problem: anyone can break the invariant. Classes (lesson 10) fix it.

For wonder: numbers that know their own derivative (optional, 5 min)

Code Expert Exercise 9 has you build dual numbers $a + b\varepsilon$ with the strange rule $\varepsilon^2 = 0$. Multiply out: $(x + \varepsilon)^2 = x^2 + 2x\varepsilon$, and $(x + \varepsilon)^3 = x^3 + 3x^2\varepsilon$. The ε-part is the derivative! This holds for every polynomial, and with a little more work for sin, exp and the rest: $f(x + \varepsilon) = f(x) + f'(x)\,\varepsilon$. So if you write a struct for dual numbers with overloaded + and *, and pass $x + 1\varepsilon$ to any function written with those operators, the result carries $f'(x)$ for free, exact up to rounding, without any formula for the derivative. This is forward-mode automatic differentiation, and machine learning libraries use the same idea to compute the gradients of models with millions of parameters. Operator overloading is what makes it invisible: the function doesn't know it's being differentiated.
