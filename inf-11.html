1. The story: the golem walks every shelf

The workshop has grown. There is the long row of jars from lesson 5, numbered so you can walk straight to jar 17. There is a chain of rings hanging from the ceiling, where a new ring can be clipped in anywhere, but to find the tenth you must count along from the first. There is a sack of tokens, where every token is there at most once and you can ask "is the red one in?" and get an answer at once, but the tokens have no order. And there is a drawer of the same tokens, sorted.

The golem is asked: "Count how many items are red." For the jars it knows how: jar 0, jar 1, jar 2. For the chain, the sack and the drawer it is stuck: no numbers.

So each store gets a guide, a small wooden marker. You ask the store for the marker at its first item, and for the place just behind its last item. The marker can do two things: show you the item it stands at, and step on to the next one. That's all. With those two moves, the golem walks every store the same way.

In C++: the stores are containers, the marker is an iterator; "the marker at the first item" is c.begin(), "just behind the last" is c.end(), "show the item" is *it, "step on" is ++it (p. 174).

2. Containers (script 14.1)

A container is a collection of elements plus operations on it (p. 171). The standard library has several, because applications have different needs: only appending, rarely removing, often searching, … Each has characteristic strengths (+), weaknesses (−) and neutral properties (○):

containergood atweak atalso
std::vector<T>access by index v[i]; little memoryinserting or removing in the middle; searchingduplicates allowed; insertion order
std::list<T>inserting and removing anywhere (push_front, push_back, …)no index access; more memoryduplicates allowed; insertion order
std::unordered_set<T>"is e contained?", inserting, removingno order; no index accessno duplicates
std::set<T>like unordered_set, and the elements are sorteda bit slower than unordered_setno duplicates

A set models a mathematical set: $\{1, 2, 1\} = \{1, 2\} = \{2, 1\}$ (p. 172). s.insert(x) adds x if it isn't there yet. How they work inside (hash tables, red-black trees) is a topic of later courses. The script's use case (p. 172–173): read pairs "name score" and list everyone with at least 50 points once, which a std::set<std::string> does by itself: duplicates vanish, and the names come out in alphabetical order. That is coding task 1.

Worked example 1: which container?

  1. Ten thousand temperatures, read once, then accessed by day number.
    Answer

    std::vector: index access, compact.

  2. All different words of a book, printed alphabetically.
    Answer

    std::set<std::string>: no duplicates, sorted.

  3. A queue at a ticket counter: people join at the back, leave at the front, and sometimes someone in the middle gives up.
    Answer

    std::list: inserting and removing anywhere is cheap, and nobody asks for "the 57th person".

  4. Has this student ID already voted? (thousands of checks)
    Answer

    std::unordered_set: the fastest "contained?" check, order irrelevant.

3. Iterators (script 14.2)

Every container c offers (p. 174):

  • c.begin(): an iterator pointing to the first element;
  • c.end(): an iterator pointing behind the last element (not to an element!);
  • *it: the element the iterator points to (dereference);
  • ++it: advance by one position.

An iterator's type belongs to its container: std::vector<int>::iterator, std::list<int>::iterator. Shorten it with a type alias, using ivit = std::vector<int>::iterator;, or let the compiler find it with auto.

Negating every element (Example 14.6):

#include <iostream>
#include <vector>

int main() {
  std::vector<int> v = {1, 2, 3};
  for (std::vector<int>::iterator it = v.begin(); it != v.end(); ++it)
    *it = -*it;
  for (int x : v)
    std::cout << x << " ";
  std::cout << "\n";
  return 0;
}
-1 -2 -3

Since end() is one place behind the last element, the loop condition is it != v.end(), and *v.end() is never allowed. An empty container has begin() == end(): the loop doesn't run at all, without a special case. The pair (begin, end) describes the half-open range [begin, end): begin included, end excluded, exactly like indices 0 ≤ i < n.

Why iterators? (p. 175) They access every container in the same way, so the user stays independent of the container's implementation. The same loop works for a vector, a list, a set:

#include <iostream>
#include <list>
#include <set>

int main() {
  std::list<int> l = {3, 1, 2};
  l.push_front(0);                   // l = {0, 3, 1, 2}
  for (auto it = l.begin(); it != l.end(); ++it)
    std::cout << *it << " ";
  std::cout << "\n";
  std::set<int> s = {3, 1, 2, 1};    // duplicates vanish, sorted
  for (auto it = s.begin(); it != s.end(); ++it)
    std::cout << *it << " ";
  std::cout << "\n";
  return 0;
}
0 3 1 2
1 2 3

The iterator loop in four questions

  1. Which range? The whole container: c.begin() to c.end(). A part: two iterators, e.g. v.begin() + i to v.begin() + j (only for vectors, which can jump).
  2. Which iterator type? T::iterator to change elements, T::const_iterator to read a const container (section 5); or simply auto.
  3. The loop head? Always for (it = begin; it != end; ++it). Never <=, never *end.
  4. The body? The element is *it; write *it = … to change it. In a container of structs, a member is (*it).name.

4. Ranges, algorithms and the range-based for (script 14.2)

Many algorithms of the standard library take an iterator pair instead of a container (p. 175). That is more general: it works for every container, and also for part of one. Example 14.7, negating as a function:

#include <iostream>
#include <vector>

using iterator = std::vector<int>::iterator;

// POST: every element in [begin, end) is negated
void neg(iterator begin, iterator end) {
  for (iterator it = begin; it != end; ++it)
    *it = -*it;
}

int main() {
  std::vector<int> v = {1, 2, 3, 4, 5, 6};
  neg(v.begin(), v.begin() + (v.size() / 2));   // negates half of the data
  for (int x : v)
    std::cout << x << " ";
  std::cout << "\n";
  return 0;
}
-1 -2 -3 4 5 6

The algorithms library (#include <algorithm>) has more than 100 such functions on ranges [begin, end), for example std::sort(v.begin(), v.end()) (ascending), std::find, std::fill (p. 176). Not every algorithm works for every container: an unordered_set can't be sorted, and v.begin() + 3 only works for containers that can jump, like vector.

Range-based for (p. 176): the iterator loop over a whole container can be written shorter, and the compiler translates it back:

for (int e : l)        // e is a COPY of each element: read only
  std::cout << e;
for (int& e : l)       // e is a REFERENCE to each element: can change it
  e += 3;

Without &, changing e changes only the copy. That is the reference rule of lesson 5 once more.

5. Const iterators (script 14.3)

Every container also offers a const_iterator, which only grants read access. Calling begin() on a const container automatically gives a const_iterator. So this does not compile (Example 14.8):

const auto x = std::vector<int>{1, 2, 3};
for (std::vector<int>::iterator it = x.begin(); it != x.end(); ++it)  // error
  std::cout << *it;

A const_iterator, or auto, works (Examples 14.9 and 14.10). This matters most for parameters: in void print(const std::vector<int>& v), v is const, so its iterators are const_iterators. If you need a const_iterator from a non-const container, use x.cbegin() and x.cend().

#include <iostream>
#include <vector>

using cit = std::vector<int>::const_iterator;

// POST: the elements of v have been printed, separated by spaces
void print(const std::vector<int>& v) {
  for (cit it = v.begin(); it != v.end(); ++it)
    std::cout << *it << " ";        // reading is fine; *it = 0 would not compile
  std::cout << "\n";
}

int main() {
  std::vector<int> v = {1, 2, 3};
  print(v);
  return 0;
}

Coding task 1: who passed? (script Examples 14.3 and 14.5)

The input is a sequence of pairs "name percentage", one per Code Expert submission; the same name may appear several times. Print every name that has at least one submission with 50 % or more, once each, in alphabetical order, separated by spaces.

You'll need these

An input loop while (std::cin >> name >> score) (lesson 4), std::set and insert (section 2), and the range-based for (section 4).

What the contract forces (before any idea)
  • Given: any number of pairs, possibly none.
  • Must hold at the end: each qualifying name printed exactly once, sorted.
  • The gap to fill: who removes the duplicates, and who sorts? (Answer: the container, if you pick the right one.)

Coding task 2: negate a part (script Example 14.7)

Write neg(begin, end), which negates every element of the range [begin, end), and call it so that the elements with indices from to to − 1 are negated.

You'll need these

The iterator loop and v.begin() + i (section 4).

What the contract forces (before any idea)
  • Given: a vector and 0 ≤ from ≤ to ≤ n.
  • Must hold at the end: exactly the elements with index from ≤ i < to are negated; the others unchanged.
  • The gap to fill: turning the indices into iterators, and the half-open range.

Try it yourself: write the body of neg and the call, then press Check.

#include <iostream>
#include <vector>

// PRE:  [begin, end) is a valid range
// POST: every element in [begin, end) is negated

  // todo

int main() {
  int n;
  std::cin >> n;
  std::vector<int> v(n);
  for (int i = 0; i < n; ++i)
    std::cin >> v[i];

  1. Which iterators belong to indices from and to?
    My answer

    v.begin() + from points to element from; v.begin() + to to element to, which is exactly the first one not to negate. The half-open range fits the indices.

  2. What happens for from == to?
    My answer

    An empty range: begin == end, the loop doesn't run, nothing changes. No special case.

  3. Why does neg not need the vector itself?
    My answer

    The iterators lead to the elements; *it = -*it changes them inside the vector. The function doesn't know the size or the container, only its range.

Coding task 3: common days, efficiently (Informatik exam summer 2019, task 9 (b), 8 points)

Bob noted the days of the year on which he worked on programming exercises, for 2017 and for 2018. How many days appear in both lists? No list contains a day twice. Part (a) of the exam used two nested index loops (exercise 1). Part (b): first sort both vectors with std::sort, then walk them with one iterator each, side by side, so that each vector is passed only once. Example: {1, 35, 90, 5, 27, 3} and {5, 90, 7, 27, 35, 101} have 4 common elements, {5, 27, 35, 90}.

You'll need these

std::sort(v.begin(), v.end()) from <algorithm> (section 4), two iterators and the "end" test for each.

What the contract forces (before any idea)
  • Given: two vectors without duplicates; they may be changed (they are passed by reference, not const).
  • Must hold at the end: the size of the intersection.
  • The gap to fill: in two sorted lists, which iterator may safely move on when the elements differ?

Try it yourself: complete the function, then press Check. Input: n and n numbers, m and m numbers.

#include <algorithm>
#include <iostream>
#include <vector>

using Iterator = std::vector<int>::iterator;

// PRE:  no vector contains an element twice
// POST: returns the number of elements that appear in both vectors;
//       vec1 and vec2 are sorted afterwards
int efficiently_calculate_intersection(std::vector<int>& vec1,
                                       std::vector<int>& vec2) {
  // todo: sort both vectors
  Iterator vec1It = vec1.begin();
  Iterator vec2It = vec2.begin();
  int number_matching_elements = 0;
  // todo: walk both vectors side by side
  return number_matching_elements;
}

int main() {
  int n, m;
  std::cin >> n;
  std::vector<int> a(n);
  for (int i = 0; i < n; ++i) std::cin >> a[i];
  std::cin >> m;
  std::vector<int> b(m);
  for (int i = 0; i < m; ++i) std::cin >> b[i];
  std::cout << efficiently_calculate_intersection(a, b) << "\n";
  return 0;
}
  1. Both sorted; *vec1It < *vec2It. Why may vec1It move on?
    My answer

    Everything still ahead in vec2 is ≥ *vec2It > *vec1It. So *vec1It can't occur in vec2 any more: skip it. Symmetrically for >.

  2. And when they're equal?
    My answer

    A common element: count it and advance both (no duplicates, so neither occurs again).

  3. The loop condition?
    My answer

    vec1It != vec1.end() && vec2It != vec2.end(): as soon as one list is used up, no more matches are possible, and dereferencing an end iterator is forbidden.

  4. Write it.
    Answer (written by StudyHub; no official solution exists; checked by compiling)

    Frame: sort; then one loop with three cases, each advancing at least one iterator.

    The golem's stepsWhat you write

    Put both rows in order, smallest first.

    std::sort(vec1.begin(), vec1.end());
std::sort(vec2.begin(), vec2.end());

    One marker on each row. While neither marker has fallen off its row: the marker on the smaller item steps on; if both items are equal, count one and both step on.

    while (vec1It != vec1.end() && vec2It != vec2.end()) {
  if (*vec1It < *vec2It) {
    ++vec1It;
  } else if (*vec1It > *vec2It) {
    ++vec2It;
  } else {
    ++number_matching_elements;
    ++vec1It;
    ++vec2It;
  }
}
    The program in one piece
    #include <algorithm>
#include <iostream>
#include <vector>

using Iterator = std::vector<int>::iterator;

// PRE:  no vector contains an element twice
// POST: returns the number of elements that appear in both vectors;
//       vec1 and vec2 are sorted afterwards
int efficiently_calculate_intersection(std::vector<int>& vec1,
                                       std::vector<int>& vec2) {
  std::sort(vec1.begin(), vec1.end());
  std::sort(vec2.begin(), vec2.end());
  Iterator vec1It = vec1.begin();
  Iterator vec2It = vec2.begin();
  int number_matching_elements = 0;
  while (vec1It != vec1.end() && vec2It != vec2.end()) {
    if (*vec1It < *vec2It) {
      ++vec1It;
    } else if (*vec1It > *vec2It) {
      ++vec2It;
    } else {
      ++number_matching_elements;
      ++vec1It;
      ++vec2It;
    }
  }
  return number_matching_elements;
}

int main() {
  int n, m;
  std::cin >> n;
  std::vector<int> a(n);
  for (int i = 0; i < n; ++i) std::cin >> a[i];
  std::cin >> m;
  std::vector<int> b(m);
  for (int i = 0; i < m; ++i) std::cin >> b[i];
  std::cout << efficiently_calculate_intersection(a, b) << "\n";
  return 0;
}

  5. Tests.
    My answer

    The exam's example; an empty vector; no common element; identical sets in different order; one element each; lists of different lengths where the last element matches (50), which checks that the loop doesn't stop too early.

  6. Why is this faster than part (a)?
    My answer

    Nested loops compare every pair: n · m comparisons. After sorting, every step advances at least one iterator, so the walk takes at most n + m steps. Sorting itself costs about n log n (algorithms course), still far less than n · m for long lists.

  2. Condition: both iterators not at their end.
  3. Three cases, each advances something; otherwise the loop never ends.

In short: "smaller one steps; equal: count, both step".

    My answer

Summary: what to keep from lesson 11

  • Containers: vector (index access, compact), list (insert and remove anywhere, no index), unordered_set (fast "contains", no duplicates, no order), set (like unordered_set but sorted). Choose by the most frequent operation.
  • Iterators: c.begin() first element, c.end() behind the last; *it element, ++it next. Loop: for (auto it = c.begin(); it != c.end(); ++it).
  • Ranges [begin, end): functions and the algorithms library (std::sort, std::find, …) take iterator pairs; works on whole containers and on parts.
  • Range-based for: for (T e : c) reads copies, for (T& e : c) can change.
  • Const: a const container gives const_iterators, read only; cbegin()/cend() from a non-const one.

For wonder: one loop, a hundred algorithms (optional, 5 min)

The idea behind this chapter is due to Alexander Stepanov, who designed the C++ standard template library in the early 1990s. His insight: an algorithm like "find" or "sort" doesn't care what a container is, only how you can move through it. So he sorted iterators into families by what they can do: step forward only (a singly linked list), step both ways (std::list), or jump anywhere (vector, like v.begin() + 3). Each algorithm states the weakest family it needs: std::find only steps forward, std::sort needs jumps. That is why you can't sort a list with std::sort (it has its own l.sort()), and why the script says the more than 100 algorithms work with the 17 standard containers "and our own": write an iterator for your container in lesson 12, and they all work on it.
