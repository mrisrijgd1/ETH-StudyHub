1. The story: the golem lays out a row

The train of lesson 12 was flexible, but slow to search: to reach wagon 500, the golem walked past 499 couplings. For its jars, the golem wants the opposite: a row of shelves side by side, all the same width, so that jar 500 is simply 500 shelf widths from the first. No walking, just measuring.

So it asks the store room not for one shelf at a time but for a whole row at once: "Seven shelves, in one piece, please." It gets back a single note: where the row starts. Everything else follows from counting shelf widths.

The trouble comes when the row is full and an eighth jar arrives. A row can't be stretched: there may be someone else's shelves right behind it. The golem has to ask for a new, longer row somewhere else, carry every jar over, and return the old row. If it asks for just one shelf more each time, it will be carrying jars all day. So it asks for twice as many.

In C++: the row is a dynamic array, made with new int[7], which returns a pointer to the first element (p. 216–217). Measuring is pointer arithmetic: p + 500. Returning the row is delete[]. And asking for twice as many is how std::vector grows (p. 227–228).

2. Dynamic arrays and pointer arithmetic (script 18.1.1)

A std::vector can have a size known only at runtime, can grow, and stores its elements contiguously, side by side in memory, which is what allows fast access by index (p. 216). Allocating each element with its own new would scatter them over the heap. Instead we allocate a whole chunk:

new T[n] allocates memory for n consecutive objects of type T, an array of length n (n is an int expression, possibly from input). Its value is the address of the first element; its type is T* (p. 216–217). An initialiser list may follow: new int[7]{1, 2, 3, 4, 5, 6, 7}. Without one, the ints are not initialised.

Pointer arithmetic (p. 217–219), for a pointer p to the first element of an array of length n:

  • p + i, for 0 ≤ i ≤ n, points to the element with index i; p + n points behind the array, like end() (Figure 18.3). Anything outside [0, n] is undefined behaviour.
  • p[i] is shorthand for *(p + i), the subscript operator.
  • q - i moves back, as long as you stay inside the array (or right behind it).
  • q1 - q2, for two pointers into the same array at indices k1 and k2, is the number k1 − k2.

Pointer arithmetic counts elements, not bytes: for an int* (4 bytes per int on usual machines), p + 1 is 4 addresses further (p. 218). And pointers and integers don't mix: int* ptr = 5; and int a = ptr; are compiler errors.

The script's example (Figure 18.4):

#include <iostream>

int main() {
  int* p0 = new int[7]{1, 2, 3, 4, 5, 6, 7};   // p0 points to 1st element
  int* p3 = p0 + 3;                            // p3 points to 4th element
  *(p3 + 2) = 600;                             // set value of 6th element to 600
  std::cout << *(p0 + 5) << "\n";              // output 6th element's value
  std::cout << p0[5] << " " << p3[-1] << " " << (p3 - p0) << "\n";
  delete[] p0;
  return 0;
}
600
600 3 3

p3[-1] is *(p3 - 1), the element just before p3, which is fine because it is still inside the array. The last line frees the array; section 5 explains delete[].

3. Walking arrays, and arrays in functions (script 18.1.2–18.1.3)

To visit every element, let a pointer start at the first and stop at the address behind the last (p. 219):

char* p = new char[3]{'x', 'y', 'z'};
for (char* it = p; it != p + 3; ++it)
  std::cout << *it << " ";        // output current element

That is the iterator loop of lesson 11, with a plain pointer as the iterator. The index loop for (int i = 0; i < 3; ++i) std::cout << p[i]; does the same, but each p[i] computes the address p + i·s again, while ++it just steps once. The script's picture (p. 220): reading a book page by page, against closing it after every page and opening it again at the next page number. For a walk, prefer the pointer.

Arrays in functions (p. 220–221): by convention, an array or part of one is passed as two pointers, begin to the first element and end behind the last. [begin, end) is the segment; it is empty if begin == end.

// PRE:  [begin, end) is a valid range
// POST: every element within [begin, end) was set to value
void fill(int* begin, int* end, int value) {
  for (int* p = begin; p != end; ++p)
    *p = value;
}

Called as fill(p, p + 5, 1); for the whole array of 5, or fill(p + 1, p + 3, 0); for indices 1 and 2. A function that only reads takes const int* (lesson 12: the ints are read-only through the pointer).

Pointer ranges in four questions

  1. Which range? Indices i to j − 1 are [a + i, a + j); the whole array of n is [a, a + n).
  2. Read or write? Reading only: const int*. Writing: int*.
  3. The loop? for (int* p = begin; p != end; ++p), element *p, next element *(p + 1), last element *(end - 1).
  4. The empty range? begin == end: the loop doesn't run; but *begin and *(end - 1) are forbidden, so guard them with if (begin < end) or if (begin != end).

4. An array-based vector (script 18.2)

With arrays we can build our own vector (p. 221):

class our_vector {
  int* elements;   // pointer to first element in array
  int count;       // number of elements
public:
  our_vector(int size) : elements(new int[size]), count(size) {}
  int size() const { return count; }
  int& operator[](int i) { return elements[i]; }
  const int& operator[](int i) const { return elements[i]; }
  void print(std::ostream& sink) const {
    for (int* p = elements; p != elements + count; ++p)
      sink << *p << " ";
  }
  using iterator = int*;                            // pointers are iterators!
  iterator begin() { return elements; }             // first element
  iterator end() { return elements + count; }       // past the last element
};

(The script's constructor lists count(size) before elements(…); we list them in the order they are declared, because members are always initialised in declaration order, whatever the list says.) Four things to notice (p. 222–224):

  • operator[] returns int&, so v[0] = 123 works. A second, const version returning const int& lets you read from a const our_vector; the compiler picks the right one. A checked variant at(i) would first assert(0 <= i && i < count).
  • print walks the array with a pointer, and operator<< can call it, as in lesson 9.
  • The iterator is just int*: a pointer already has *, ++ and !=. So for (int& i : v) i += 3; and the standard algorithms work at once.
  • The constructor leaves the elements uninitialised, like new int[size] itself.

5. Memory management with dynamic arrays (script 18.3)

What happens here (p. 224–225)?

for (int i = 0; i < 1000000; ++i) {
  our_vector v = our_vector(1000000);
}

Each v dies at the end of the round, but its million ints stay: a leak of a million ints per round. Every new[] needs its matching delete[]: delete[] a; frees the array that a points to (a must come from new T[]; a is not reset and now dangles). Use delete for single objects from new, delete[] for arrays from new[]; mixing them up is undefined behaviour.

The array is made in the constructor, so it is freed in the destructor. And then the rule of three of lesson 13 applies: our_vector w = v; would copy only the pointer, and both destructors would delete the same array (p. 225–226). So (p. 226–227):

our_vector::~our_vector() {
  delete[] elements;
}

our_vector::our_vector(const our_vector& v)
  : elements(new int[v.count]), count(v.count) {
  for (int i = 0; i < count; ++i)
    elements[i] = v.elements[i];
}

our_vector& our_vector::operator=(const our_vector& v) {
  if (this != &v) {                        // no self assignment
    our_vector copy = v;                   // copy constructor
    std::swap(elements, copy.elements);    // swap pointer
    std::swap(count, copy.count);          // swap count
  }
  return *this;                            // convention
}

Copy-and-swap now swaps both members, and the destructor of copy frees the old array.

6. Inserting and removing: how a vector grows (script 18.4)

A vector must grow and shrink: push_back, push_front, remove(i) (p. 227). But an allocated block can't be resized. One idea: allocate more than needed and keep the elements in the middle, with pointers to the first and last element, so they can grow in both directions (Figure 18.8). Eventually the block is full anyway, and then there is no way around it: allocate a larger block, copy every element over, free the old block (p. 228). That is expensive, so it should happen rarely.

Removing or inserting in the middle is costly too: every element behind the gap must be shifted by one to keep the array contiguous (Figure 18.10). That is where a linked list wins. Overall (p. 228), vectors are usually faster, except for inserting and removing at the front, and they need much less memory: about n ints for n elements, against about 3n for our list (each node also holds a pointer of 8 bytes).

Doubling. How much larger should the new block be? Growing by one element at a time means copying 1, then 2, then 3, … elements: for n push_backs about n²/2 copies. Growing to double the size means that a copy happens only at sizes 1, 2, 4, 8, …, and all copies together are fewer than 2n. On average, every push_back costs a constant amount of work. The winter 2018/19 exam (task 6) asks exactly for this push_back: coding task 4.

Worked example 2: counting the copies

A vector starts with room for 1 element. We push_back 9 elements.

  1. Growing by one each time it is full: how many element copies in total?
    Answer

    It is full before every push from the second on, with 1, 2, …, 8 elements: 1 + 2 + … + 8 = 36 copies.

  2. Doubling each time it is full: when does it grow, and how many copies?
    Answer

    It is full at sizes 1, 2, 4 and 8: it grows to 2, 4, 8 and 16, copying 1 + 2 + 4 + 8 = 15 elements. For a million elements the difference is about 500 billion copies against 2 million.

Coding task 2: cyclic shift (IFMP exam January 2017, task 4, 8 points)

Write cyclic_shift(begin, end): every element of the range moves one place to the left, and the first element moves to the back. (1, 2, 3, 4, 5) becomes (2, 3, 4, 5, 1). An empty range is left alone. The exam's hint: store the first element; walk from the first to the second-to-last element, replacing each by its successor; finally put the stored element last.

You'll need these

*(p + 1) and *(end - 1) (section 2) and the pointer-range method, question 4.

What the contract forces (before any idea)
  • Given: a valid range, possibly empty.
  • Must hold at the end: a_2, …, a_n, a_1 in the range; nothing outside it changed.
  • The gap to fill: a_1 is overwritten in the first step, so it must be saved; and the loop must stop one early, because the last element has no successor.

  1. Why must the loop stop at end - 1?
    My answer

    The body reads *(p + 1). For p = end − 1 that would be *end, behind the range. The last element gets a_1 after the loop instead.

  2. What protects the empty range?
    My answer

    if (begin < end). Without it, *begin and *(end - 1) would read outside the range. (The official solution compares with <; begin != end works as well.)

  3. Does a range of one element need a special case?
    My answer

    No: the loop doesn't run (begin is not < end − 1), and a_1 is written back to its own place.

  4. Write it.
    Answer (official solution, IFMP January 2017; checked by compiling)

    Frame: guard the empty range; save, shift, put back.

    The golem's stepsWhat you write

    If there is at least one jar: take the first jar off the row and hold it.

    if (begin < end) {
  int a_1 = *begin;

    From the first shelf to the second-to-last: move the neighbour's jar onto this shelf.

      for (int* p = begin; p < end - 1; ++p)
    *p = *(p + 1);

    Put the held jar on the last shelf.

      *(end - 1) = a_1;
}
    The program in one piece
    #include <iostream>

// PRE:  [begin, end) is a valid range, possibly empty
// POST: the sequence a_1, a_2, ..., a_n of numbers in the range
//       [begin, end) is replaced by the sequence a_2, ..., a_n, a_1
void cyclic_shift(int* begin, int* end) {
  if (begin < end) {
    int a_1 = *begin;
    for (int* p = begin; p < end - 1; ++p)
      *p = *(p + 1);
    *(end - 1) = a_1;
  }
}

    My answer

    The exam's (1, 2, 3, 4, 5); a middle part (indices 1 to 3), so the elements outside must stay; an empty range; a single element; the last two elements.

  6. How would you shift to the right instead: (1, 2, 3) to (3, 1, 2)?
    My answer

    Save the last, int a_n = *(end - 1);, walk backwards for (int* p = end - 1; p > begin; --p) *p = *(p - 1);, then *begin = a_n;. The direction of the walk matters: forwards, you would overwrite the values you still need.

Patterns used: save one, shift the rest a pointer walks an array range

How to write this under exam pressure
  1. Guard first: if (begin < end).
  2. Save what you will overwrite.
  3. A loop reading *(p + 1) stops at end - 1.

In short: "guard, save, shift, put back".

What the contract forces (before any idea)
  • Given: a vector v of any size, possibly 0.
  • Must hold at the end: the copy has its own array of the same size and the same elements; changing one vector never changes another; old arrays are freed exactly once.
  • The gap to fill: the initialiser list already allocates the new array; you copy the elements, and in operator= you exchange the contents with a copy.

Coding task 4: a vector that doubles (Informatik exam winter 2018/19, task 6, 12 points)

The class avec stores its elements in an array of max_size slots, of which the first size are used. Complete push_back: when the array is full, double max_size first: allocate an array of twice the size, copy the elements over, free the old array. Then append. Appending 3 to the full vector 1, 2 (maximum size 2) gives 1, 2, 3, _ (maximum size 4). The vector starts with room for 32. The program appends 1, …, n and reports size, maximum size and sum.

You'll need these

new int[…] and delete[] (section 5), a pointer walk with two pointers at once, and doubling (section 6).

What the contract forces (before any idea)
  • Given: size ≤ max_size; the elements in elements[0 .. size − 1].
  • Must hold at the end: the old elements in order, new_element after them, size one larger; max_size doubled exactly when it was full; no old array left behind.
  • The gap to fill: the order of copy, free and switch, so that no element and no array is lost.

  1. When is the array full?
    My answer

  2. In which order: copy, delete[] elements, elements = new_elems?
    My answer

    Exactly that order. Free before copying and you copy from freed memory; switch the pointer before freeing and you lose the only pointer to the old array (a leak) or free the new one.

Worked examples: a mixed set before the exercises

Worked example 3: index or pointer?

int* a = new int[4]{3, 1, 4, 1};
int s = 0;
for (int* p = a + 1; p != a + 4; ++p)
  s += *p - *(p - 1);
  1. What is s?
    Answer

    (1 − 3) + (4 − 1) + (1 − 4) = −2 + 3 − 3 = −2. That is a[3] − a[0]: the differences telescope.

  2. Write the same loop with indices.
    Answer

    for (int i = 1; i < 4; ++i) s += a[i] - a[i - 1];. p = a + i, and *(p - 1) is a[i - 1].

Worked example 4: delete or delete[]?

  1. Which is right for each: int* x = new int(5);, int* y = new int[5];, lnode* n = new lnode(1, nullptr);?
    Answer

    delete x;, delete[] y;, delete n;. Square brackets exactly when the object came from new T[…]. Note that new int(5) is one int with value 5, and new int[5] five ints.

  2. And for int* z = y + 2;: may you write delete[] z;?
    Answer

    No: delete[] needs the pointer that new[] returned, the start of the array. Freeing through z is undefined behaviour.

Exercise 4 (IFMP exam August 2016, task 8 (a) and (b), old exam) · 6 points

A DoublingStack keeps its elements in a doubly linked list of arrays, each twice as large as the one before; new memory is needed only when the top array is full.

struct Node { // for one array in the list
  int* values; int size; Node* next; Node* prev; // data members

  Node (int s, Node* p)
   : values (new int[s]), size (s), next (0), prev (p) // constructor
  {}
  ~Node() { delete[] values; } // destructor
};

class DoublingStack {
  Node* first; Node* top; int pos; // data members
public:
  DoublingStack ()
  : first (new Node (1, 0)), top (first), pos (0) // default constructor
  {}
  // POST: puts value on the stack
  void push (int value) {
    if (pos == top->size) { // top array full
      top->next = new Node (2 * top->size, top);
      top = top->next; pos = 0;
    }
    top->values[pos++] = value;
  }
  ...
};

(a) How many arrays does an initially empty DoublingStack contain after push has been called N times, for N = 7 and N = 33? (2 points) (b) Implement the destructor ~DoublingStack(), so that it frees all allocated memory. (4 points)

Solution

Frame: (a) count capacities 1, 2, 4, …; (b) the stack destructor of lesson 13, walking from first. (Official solution, IFMP August 2016.)

(a) N = 7: 3 arrays (1 + 2 + 4 = 7 slots, all full). N = 33: 6 arrays (1 + 2 + 4 + 8 + 16 = 31 < 33, so a sixth array of 32 is needed). (b)

~DoublingStack() {
  Node* node = first;
  while (node != 0) {
    Node* tmp = node;
    node = node->next;
    delete tmp;
  }
}

delete tmp runs the Node's destructor, which does delete[] values: each node frees its own array. The exam's part (c), pop, deletes the top array when it is empty: try it as a challenge.

Summary: what to keep from lesson 14

  • Arrays: new T[n] gives a T* to the first of n contiguous elements; free with delete[] (with brackets, through the start pointer).
  • Pointer arithmetic: p + i is index i, p + n is behind the end (never dereference); p[i] is *(p + i); q - p is the index distance. Stay inside [0, n].
  • Ranges: functions take (begin, end); loop for (int* p = begin; p != end; ++p); guard *begin and *(end - 1) against the empty range. Pointers are iterators.
  • Array-based vector: array plus count; operator[] in a non-const and a const version; rule of three with delete[] and deep copies.
  • Growing: a block can't be resized; allocate a larger one, copy, free the old. Double the size, so copying stays rare. Inserting or removing in the middle shifts elements; that is where lists are better.

For wonder: why exactly double? (optional, 5 min)

Doubling makes every push_back cost a constant amount of work on average: in "amortised constant time", as the algorithms course will call it. But why 2? Any factor larger than 1 gives the same average; the factor only trades memory against copying. With factor 2 there is a curious catch: the new block is always larger than all the old blocks put together (1 + 2 + 4 = 7 < 8), so the memory freed earlier can never be reused for the next block. That is why some libraries grow by 1.5 instead: after a few steps, the freed blocks add up to enough room for the next one. The C++ standard doesn't fix the factor; GCC's library doubles, Microsoft's grows by 1.5. You can watch your own: print v.capacity() after each push_back.
