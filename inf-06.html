1. The story: the golem learns to read

The golem could only ever hold numbers. Its boxes knew nothing of letters. So when the surveyors asked it to keep the names of their gardens, the scribes made a codebook: every letter gets a number. "A" is 65, "B" is 66, and so on in order; the small letters start at 97; even the space has a number, 32. The golem stores the number, and only when it writes to the scroll does it look up the codebook and draw the letter.

Because the letters are numbered in order, the golem can calculate with them. "The letter after C" is just 67 + 1. "How far is G from A?" is 71 − 65 = 6. And a capital is always exactly 32 below its small letter.

The general of the old kingdom liked this very much. To send a secret order, he had every letter moved three places further in the alphabet, wrapping from Z back to A. A messenger who read "DWWDFN" learnt nothing; the golem at the other end moved every letter back by three and read "ATTACK".

In C++: the letter in a box is a value of type char, the codebook is ASCII, a word is a std::string, a row of characters that behaves like a vector, and the general's trick is the Caesar cipher (script 9.2). The script's starting point (p. 114): "Texts comprise characters. A character is a value of the fundamental type char."

2. The type char

The type char (p. 114) represents printable characters such as 'a' and control characters such as '\n' (new line). A character literal is written in single quotes: char c = 'a';. Double quotes make a string literal, "a", a text: a different type.

char is formally an integer type: its values convert to int and unsigned int, and all arithmetic operators work on it, even meaningless ones like 'a' / 'b'. A char usually takes 8 bits (one byte).

One rule from lesson 2 decides almost every "type and value" question with characters: in arithmetic, a char is converted to int first. So 'a' + 1 is an int, 98, and std::cout prints a number. To get a character back, convert it with char(…) or store it in a char variable.

#include <iostream>

int main() {
  char c = 'a';
  std::cout << c << " " << int(c) << "\n";        // the letter, its code
  std::cout << c + 1 << " " << char(c + 1) << "\n";  // int 98, char 'b'
  char d = c + 2;                                   // stored as char: 'c'
  ++d;                                              // still a char: 'd'
  std::cout << d << " " << ('z' - 'a') << "\n";
  return 0;
}

3. ASCII: the codebook

The ASCII code (American Standard Code for Information Interchange, p. 114) fixes the numbers 0 to 127 for the characters, on every common computer. The ranges you need:

'a', 'b', …, 'z'97, 98, …, 122
'0', '1', …, '9'48, 49, …, 57

You don't need to learn the numbers by heart: write 'a', not 97, and the compiler fills in the code. What matters is that each block is in order and without gaps. That is why the script's Example 9.3 (p. 115) works:

#include <iostream>

int main() {
  for (char c = 'a'; c <= 'z'; ++c)
    std::cout << c;
  std::cout << "\n";
  return 0;
}

Three letter patterns

  1. Is c a lowercase letter? 'a' <= c && c <= 'z'. The same for 'A'…'Z' and the digits '0'…'9'.
  2. What number does the digit character c stand for? c - '0'. '7' - '0' is 55 − 48 = 7.
  3. Which capital belongs to the lowercase c? c - 'a' + 'A': position in the alphabet, then the same position among the capitals. Store it in a char (or write char(…)), or you get a number.

All three use only the order of the blocks, never the codes themselves.

#include <iostream>

int main() {

}

4. Beyond ASCII: Unicode and UTF-8 (script 9.1, marked *)

128 characters are not enough for Chinese, Cyrillic, Greek, Hebrew, or even for "ä" (p. 115). Unicode numbers more than 137 000 characters from more than 150 scripts. To store them without wasting space on ordinary English text, UTF-8 uses a variable number of bytes per character (p. 115):

usable bitsbytesbit pattern
710xxxxxxx (exactly ASCII)
112110xxxxx 10xxxxxx
1631110xxxx 10xxxxxx 10xxxxxx
21411110xxx 10xxxxxx 10xxxxxx 10xxxxxx

The script continues the table up to 6 bytes and 31 bits; today's Unicode needs at most 4.

The remarkable property (p. 115): a byte starting with 10 never starts a character. So in the middle of a stream of bytes you can always find where the next character begins. And the first byte says how long the character is: for a multi-byte character, its number of leading 1s is the number of bytes.

For C++ this has one consequence you should know: a std::string stores bytes. std::string("ä").size() is 2, because "ä" (Unicode 228, 8 bits) needs the two-byte pattern. "The size is not equal to the text length if a multi-byte encoding is used" (p. 118). All exam tasks stay in ASCII.

5. The Caesar cipher (script 9.2)

In its simplest form, the Caesar cipher replaces every character by the one s places further on, wrapping around at the end (p. 115). On the alphabet, ZEBRA becomes AFCSB with a shift of 1, and YDAQZ with a shift of −1. The script shifts all 95 printable characters 32 to 126 instead of only the letters, so that, with a shift of −3, the space (32) becomes '|' (124) and 'D' (68) becomes 'A' (65).

How to compute the shifted code of c (p. 116)? c + s, except where it leaves the range 32…126. The elegant way around the case distinction is the "move to 0" trick:

  1. subtract 32: the printable characters become 0…94;
  2. add the shift and take the mathematical remainder modulo 95: the result is again in 0…94, wrapped around;
  3. add 32 back.

So the new code is 32 + mod(c - 32 + s, 95), where mod is the mathematical modulo from lesson 2: C++'s % gives a negative result for a negative left operand, so the script adds the divisor once more. Code 9.1 (p. 117), complete:

#include <iostream>
#include <ios>

// PRE:  divisor > 0
// POST: returns the mathematically defined remainder of
//       dividend / divisor with 0 <= result < divisor
int mod(int dividend, int divisor) {
  return (dividend % divisor + divisor) % divisor;
}

// POST: if c is one of the 95 printable ASCII characters, c is
//       cyclically shifted s printable characters to the right
char shift(char c, int s) {
  if (c >= 32 && c <= 126) {        // c is printable
    c = 32 + mod(c - 32 + s, 95);
  }
  return c;
}

// POST: Each character read from std::cin was shifted cyclically
//       by s characters and afterwards written to std::cout
void caesar(int s) {
  std::cin >> std::noskipws;        // do not skip whitespace from now on
  char next;
  while (std::cin >> next) {
    std::cout << shift(next, s);
  }
}

int main() {
  int s;
  std::cin >> s;
  caesar(s);                         // shift the rest of the input by s
  return 0;
}
#Khoor/#Fdhvdu$

Two details. std::cin >> std::noskipws; switches off the usual skipping of whitespace (p. 116), so spaces and line breaks are read as characters too. That is why the output starts with #: the space after the 3 in the input is read and shifted to # (35). And while (std::cin >> next) stops at the end of the input.

Worked example 3: decrypt with the script's formula (Code 9.1, p. 117)

  1. What is shift('~', 1)? ('~' is 126, the last printable character.)
    Answer

    126 − 32 + 1 = 95; mod(95, 95) = 0; 32 + 0 = 32: the space. The wrap-around from the last printable character to the first.

  2. What is shift(' ', -3)?
    Answer

    32 − 32 − 3 = −3. C++ gives -3 % 95 == -3, but mod(−3, 95) = (−3 + 95) % 95 = 92. 32 + 92 = 124: '|', as in the script's table (p. 116).

  3. How do you decrypt a text encrypted with shift s?
    Answer

    Encrypt it again with shift −s: each character moves s places back, wrapping the same way. Feeding the output above back in, as -3 #Khoor/#Fdhvdu$, prints | Hello, Caesar!: the text again, after the two shifted spaces that followed the numbers.

6. Texts: std::string

A text like "to be or not to be" could be a std::vector<char>. Texts are everywhere, so the standard library has its own type for them, std::string, with #include <string> (p. 116). It behaves like a vector of char, plus a few things only texts need. The script's list (p. 116–118):

Reading: std::cin >> word; reads one word, up to the next whitespace. Writing: std::cout << text;.

#include <iostream>
#include <string>

int main() {
  std::string name;
  std::cin >> name;                       // one word
  std::string shout = name;               // a copy
  for (int i = 0; i < std::ssize(shout); ++i) {
    if ('a' <= shout[i] && shout[i] <= 'z') {
      shout[i] = shout[i] - 'a' + 'A';     // pattern 3 of section 3
    }
  }
  shout += "!";
  std::cout << name << " -> " << shout << " (" << shout.size() << " characters)\n";
  std::cout << (name == "golem") << " " << std::string(3, '*') << "\n";
  return 0;
}

Coding task 1: a Caesar cipher on the letters (script Section 9.2, p. 115–117)

Shift every letter by s places in its alphabet, wrapping around, and keep every other character. Capitals stay capitals, small letters stay small. The script's examples: ZEBRA becomes AFCSB with s = 1 and YDAQZ with s = −1. The input is s followed by words; print each encrypted word followed by a space.

You'll need these

The mathematical mod from lesson 2, the "move to 0" trick of section 5, and the letter patterns of section 3.

What the contract forces (before any idea)
  • Given: a character c and a shift s, which may be negative or larger than 26.
  • Must hold at the end: letters move s places within their own 26-letter block; everything else is returned unchanged. caesar returns a new string of the same length.
  • The gap to fill: the formula for one letter (the script's formula, with 26 instead of 95 and the block's own start instead of 32), and the loop that builds the new string.

    My answer

    shift_letter: a character and a shift in, a character out. caesar: a text to read only (const std::string&) and a shift in, a new text out (by value).

  2. By hand: Z with s = 1, and a with s = −27.
    My answer

    Z: position 'Z' − 'A' = 25; 25 + 1 = 26; mod 26 gives 0; 'A' + 0 = A. a with −27: 0 − 27 = −27; mod(−27, 26) = 25 (C++'s % would give −1); 'a' + 25 = z.

  3. Steps. How do you treat the two blocks?
    My answer

    #include <iostream>

// PRE:  divisor > 0
// POST: returns the mathematically defined remainder of
//       dividend / divisor with 0 <= result < divisor
int mod(int dividend, int divisor) {
  return (dividend % divisor + divisor) % divisor;
}

// POST: if c is a letter, returns c shifted cyclically by s places
//       within its alphabet (upper or lower case); otherwise returns c
char shift_letter(char c, int s) {
  if ('A' <= c && c <= 'Z')
    return 'A' + mod(c - 'A' + s, 26);   // position, shift, wrap, back
  if ('a' <= c && c <= 'z')
    return 'a' + mod(c - 'a' + s, 26);
  return c;                               // not a letter: unchanged
}

// POST: returns text with every letter shifted by s (see shift_letter)
std::string caesar(const std::string& text, int s) {
  std::string result;
  for (int i = 0; i < std::ssize(text); ++i) {
    result += shift_letter(text[i], s);
  }
  return result;
}

  5. Tests.
    My answer

    Wrap forwards (Z + 1), wrap backwards (A − 1), a shift of exactly 26 (nothing changes), a shift below −26 (needs the mathematical mod), mixed case and punctuation, digits (unchanged).

  6. Why not simply c + s with an if for "past Z"?
    My answer

    It works for −26 < s < 26 with two ifs (past Z: subtract 26; before A: add 26), but not for s = 30 or s = −27. The mod handles every s in one line, which is exactly the script's argument (p. 116).

How to write this under exam pressure
  1. Move to 0: c - 'A'.
  2. Shift and wrap with the mathematical mod, never with bare % when s can be negative.
  3. Move back: 'A' + …, returned as char.
  4. Test Z + 1 and A − 1 by hand.

In short: "position, mod, back".

Coding task 2: is it a palindrome? (Informatik exam August 2020, as Code Expert Exercise 7, Task 5)

A palindrome reads the same forwards and backwards: anna, racecar. The empty word and every one-letter word are palindromes. Write the test with a loop. (Code Expert also asks for a version without loops; that one comes in lesson 7, recursion.)

You'll need these

Walking a string by index (section 6), "for all" as a search for a counterexample (lesson 5, coding task 3).

What the contract forces (before any idea)
  • Given: a string, to read only.
  • Must hold at the end: true exactly when str[i] == str[n-1-i] for every i, where n is the length.
  • The gap to fill: which pairs to compare, and where to stop so that no index leaves the string, for even and odd n.

  return false; // todo

  1. What goes in, what comes out?
    My answer

    A string to read (const std::string&), a bool out. Case matters: Anna is not a palindrome here, because 'A' ≠ 'a'.

  2. By hand: racecar (7 letters) and abca (4).
    My answer

    racecar: compare 0 with 6 (r, r), 1 with 5 (a, a), 2 with 4 (c, c); 3 is the middle, nothing to compare. abca: 0 with 3 (a, a), 1 with 2 (b, c): different, so no. Two indices, one from each end, until they meet.

  3. Where exactly to stop?
    My answer

    While i < j. For even n they cross (i = 2, j = 1 for abca's next step), for odd n they meet in the middle (i = j = 3). Either way, every pair has been compared once. For the empty string j starts at −1, and the loop doesn't run.

  4. Write it.
    Answer (written by StudyHub, checked by compiling)

    Frame: search for a counterexample with two indices from both ends; true if none is found.

    The golem's stepsWhat you write

    One finger on the first letter, one on the last.

    int i = 0;
int j = std::ssize(str) - 1;

    While the fingers haven't met: if the two letters differ, it's no palindrome. Otherwise move both fingers inwards.

    while (i < j) {
  if (str[i] != str[j]) return false;
  ++i;
  --j;
}

    All pairs matched.

    return true;
    The program in one piece
    #include <iostream>
#include <string>

// POST: returns true if and only if str reads the same
//       forwards and backwards
bool is_palindrome(const std::string& str) {
  int i = 0;                        // from the front
  int j = std::ssize(str) - 1;      // from the back (-1 if empty)
  while (i < j) {
    if (str[i] != str[j]) {
      return false;                 // counterexample
    }
    ++i;
    --j;
  }
  return true;
}

int main() {
  std::string word;
  std::cin >> word;
  if (is_palindrome(word))
    std::cout << "palindrome\n";
  else
    std::cout << "no palindrome\n";
  return 0;
}

Coding task 3: mountains (IFMP August 2018, task 6, official exam, 10 points)

A mountain is a sequence of plus and minus signs with two properties: (1) in every prefix, there are at least as many plus as minus signs; (2) over the whole sequence, there are as many plus as minus signs. Read "+" as a step up and "−" as a step down, and you can draw it. The height of a mountain is the largest surplus of plus signs over any prefix. The exam's examples, of heights 4, 5 and 3: ++++----, +++---+++++-----, +-+-++-+--+++---+-.

// POST: if c == '+', then h is increased by 1, otherwise h is decreased by 1
void climb(char c, int& h) {

  if (c == '+')

  else
    --h;
}

// PRE:  s consists of '+' and '-' only
// POST: returns true if and only if s represents a mountain
bool is_mountain(const std::string& s) {

    if (h < 0) {
      return false;       // property (1) fails: below the ground
    }
  }
  return h == 0;          // property (2): back on the ground
}

// PRE:  s represents a mountain

int height(const std::string& s) {
  assert(is_mountain(s));

    climb(s[i], h);
    if (h > max_h) {
      max_h = h;          // running maximum
    }
  }

Coding task 4: capitals, and no double spaces (Informatik exam summer 2019, task 6, 8 points)

Complete modify so that, given a text, it returns a copy (1) with all letters in capitals and (2) without redundant spaces: of several consecutive spaces, only the first is copied. The text contains only letters, digits and spaces. Example from the exam: ␣Hello␣␣1st␣World (each ␣ a space) gives ␣HELLO␣1ST␣WORLD. The exam's hint: "potentially useful ASCII values are 97 for 'a', 65 for 'A', 48 for '0' and 32 for ' '". As in the exam, a text is a std::vector<char>; main reads one line and prints the result between brackets, so you can see the spaces.

You'll need these

Pattern 3 of section 3 (lowercase to capital), and push_back from lesson 5.

What the contract forces (before any idea)
  • Given: a text to read (const text&), only letters, digits and spaces.
  • Must hold at the end: the returned text has every small letter capitalised, every other non-space character unchanged, and every run of spaces replaced by one space.
  • The gap to fill: whether to copy a space depends on the previous character. What must the loop remember from one round to the next?

  text modStr;

    char c = str[i];
    // your code
  }
  return modStr;
}

int main() {

  1. What goes in, what comes out?
    My answer

    A text to read, a new text out, built with push_back. Its length is at most the input length.

  2. By hand: a␣␣␣b. Which characters are copied?
    My answer

    a → A, copied. First space: the previous was no space, copy it. Second and third space: the previous was a space, skip. b → B, copied. Result A␣B. So the loop must remember "was the last character a space?": that is space_seen.

  3. Steps. How many cases are there, and what happens to space_seen in each?
    My answer

    Three: a small letter (copy its capital, space_seen = false), another non-space (copy it, space_seen = false), a space (copy it only if !space_seen; in any case space_seen = true). Forgetting to reset space_seen after a letter is the trap: then only the first space of the whole text would survive.

Worked example 5: counting letters (written by StudyHub)

A vector of 26 counters, one per letter, indexed by the position in the alphabet: the two big tools of lessons 5 and 6 together.

#include <iostream>
#include <string>
#include <vector>

int main() {
  std::string word;
  std::cin >> word;
  std::vector<int> count = std::vector<int>(26, 0);
  for (int i = 0; i < std::ssize(word); ++i) {
    char c = word[i];
    if ('A' <= c && c <= 'Z') c = c - 'A' + 'a';   // ignore case
    if ('a' <= c && c <= 'z') ++count[c - 'a'];    // position as index
  }
  for (int k = 0; k < 26; ++k) {
    if (count[k] > 0) std::cout << char('a' + k) << count[k] << " ";
  }
  std::cout << "\n";
  return 0;
}
  1. Why is count[c - 'a'] never out of bounds?
    Answer

    It is only reached when 'a' <= c && c <= 'z', so c - 'a' is between 0 and 25, the valid indices of a 26-element vector.

  2. Why char('a' + k) and not 'a' + k in the output?
    Answer

    'a' + k is an int, and std::cout would print 105 instead of i.

  3. The output for Mississippi?
    Answer
    i4 m1 p2 s4

    In alphabetical order, because the second loop walks the counters from a to z.

Exercise 2 (the script's Caesar cipher by hand) · 4 points

With shift from Code 9.1 (shift over all 95 printable characters), compute (1 point each): shift('A', 3), shift('}', 3) ('}' is 125), shift('!', -2) ('!' is 33), shift('\n', 5).

Solution

Frame: 32 + mod(c - 32 + s, 95) for printable c, unchanged otherwise (section 5).

shift('A', 3): 65 + 3 = 68, inside the range: 'D'. shift('}', 3): 125 − 32 + 3 = 96, mod 95 = 1, so 33: '!'. shift('!', -2): 33 − 32 − 2 = −1, mod 95 = 94, so 126: '~'. shift('\n', 5): 10 is not printable: '\n' unchanged.

Summary: what to keep from lesson 6

  • char is an integer type: 'a' is 97. In arithmetic it becomes int; write char(…) to print a character.
  • ASCII: capitals 65–90, small letters 97–122, digits 48–57, space 32, printable 32–126. Each block is in order: use 'a' <= c && c <= 'z', c - '0', c - 'a' + 'A'.

  • Methods: three letter patterns; two indices from both ends; a flag for the previous character.

For wonder: how Caesar was broken (optional, 5 min)

A Caesar cipher has only 25 useful keys: just try them all. But even if every letter is replaced by an arbitrary other letter (a "substitution cipher", with about $4\cdot 10^{26}$ keys), it falls quickly. Around 850, the scholar al-Kindi in Baghdad described the method in his Manuscript on Deciphering Cryptographic Messages: count how often each letter occurs in the secret text, exactly like Worked example 5, and compare with how often letters occur in the language. In English, E is the most common letter; in German too. The most frequent letter of a long secret text is almost certainly the replacement of E. This "frequency analysis" broke substitution ciphers for the next thousand years, and is the first known use of statistics to decode a message.
